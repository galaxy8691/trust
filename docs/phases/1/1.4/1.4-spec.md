## 0. 文件说明

本规格书定义 **Phase 1.4**（`trust_tir` crate：HIR→TIR 降级 + 移动语义检查 + 借用检查 + 区域推断 → 所有权注解完备的 TIR）的工程范围、成功标准、验收条件。

**背景：** `trust_tir` 是编译管线的第三站。它消费 `trust_hir` 产出的带类型标注的 HIR，执行：
1. **HIR→TIR 降级**：将 HIR 的控制流节点（`if`/`for`/`loop`）转换为基本块（basic blocks）+ 条件跳转；表达式转换为语句（`if`/`loop` 表达式的值通过临时变量持有）；闭包捕获的外部变量提升为隐式参数。
2. **移动语义检查（moveck）**：检测所有权转移后的使用冲突（E0382）；判定 `Copy` 类型（标量 Copy、堆类型非 Copy）。
3. **借用检查（borrowck）**：验证三模式参数调用处对称标注；借用规则（词法作用域）（≤1 可变借用 OR ≥0 只读借用）；方法调用所有权。
4. **区域推断（Region Inference）**：函数参数→返回值生命周期自动推导；`for` 循环隐式可变例外。

输出是所有权注解完备的 TIR 控制流图，供 `trust_codegen`（Phase 1.5）生成 Rust 源码。

**一句话成功：** `cargo test -p trust_tir` 全部通过，对于合法 HIR 产出所有权正确的 TIR，对于非法 HIR 收集全部所有权错误。

### 3.1 TIR 节点定义（`tir.rs`）

> 引用：`spec/trust-spec.md` §SEM-REQ-004

#### 3.1.1 顶层结构

```rust
// §设计文档 §4.1: TIR 控制流图聚合 HIR 降级后的基本块
pub struct TirProgram {
    /// 源文件路径
    pub file: String,
    /// 所有函数体（每个函数一个控制流图）
    pub functions: Vec<TirFunction>,
}

/// TIR 函数——HIR 函数降级产物，由基本块组成
pub struct TirFunction {
    pub name: String,
    /// HIR 函数参数（直接搬运自 HirFunction.params）
    /// 降级时每个参数注册为一个 TmpVar，所有权/借用信息由此字段追踪
    pub params: Vec<HirParam>,
    /// 函数返回类型（区域推断需要判断是否为引用类型）
    pub return_type: HirType,
    /// 入口基本块索引
    pub entry_block: BlockId,
    /// 所有基本块
    pub blocks: Vec<BasicBlock>,
    /// 临时变量计数器（降级时递增分配，每个函数独立序号空间）
    pub tmp_counter: u32,
    /// 闭包捕获的外部变量（隐式参数——闭包体 TirFunction.params 中也有对应条目）
    pub captured_vars: Vec<CapturedVar>,
    pub span: Span,
}

pub type BlockId = usize;
```

#### 3.1.2 基本块

```rust
/// 基本块——顺序执行的 TIR 操作序列，以终结指令结束
pub struct BasicBlock {
    pub id: BlockId,
    /// 基本块内的操作列表
    pub ops: Vec<TirOp>,
    /// 终结指令（跳转 / 返回 / 条件分支）
    pub terminator: Terminator,
    pub span: Span,
}

/// TIR 操作——基本块内的单条指令
pub enum TirOp {
    /// let tmp = value;（临时变量赋值）
    Let(TmpVar, TirValue, Span),
    /// 函数调用（含返回值写入目标临时变量）
    Call(Option<TmpVar>, TirValue, Vec<TirArg>, Span),
    /// 二元/一元运算结果写入临时变量
    Binary(TmpVar, TirValue, BinOp, TirValue, Span),
    Unary(TmpVar, UnaryOp, TirValue, Span),
    /// 移动：let b = a;（moveck 检测 a 被移动后的使用）
    Move(TmpVar, TmpVar, Span),
    /// 借用：let r = &x;
    Borrow(TmpVar, TmpVar, BorrowKind, Span),
    /// as 转换
    AsCast(TmpVar, TirValue, HirType, Span),
    /// Nop 占位
    Nop(Span),
}

/// 基本块终结指令
pub enum Terminator {
    /// 无条件跳转
    Goto(BlockId),
    /// 条件跳转：if (cond) { then_block } else { else_block }
    If(TmpVar, BlockId, BlockId),
    /// 函数返回（可选返回值）
    Return(Option<TmpVar>),
    /// 无后继（不可达代码 / 死代码）
    Unreachable,
}

/// 临时变量——TIR 降级时分配的唯一 ID
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct TmpVar(pub u32);

/// TIR 值的来源
pub enum TirValue {
    /// 临时变量引用
    Var(TmpVar),
    /// 字面量常量
    IntLiteral(i32),
    FloatLiteral(f64),
    BigIntLiteral(i64),
    StringLiteral(String),
    BoolLiteral(bool),
    /// 函数引用（用于调用）
    Function(String),
}

/// 借用类型
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum BorrowKind {
    /// &T 共享借用
    Shared,
    /// &mut T 可变借用
    Mutable,
}

/// 闭包捕获的外部变量
pub struct CapturedVar {
    pub name: String,
    pub tmp: TmpVar,
    pub kind: BorrowKind,
}

pub struct TirArg {
    pub mode: ParamMode,  // Default / InOut / Move
    pub value: TirValue,
    pub span: Span,
}
```

### 3.2 HIR→TIR 降级（`tir.rs`，~350 行）

> 引用：`spec/trust-spec.md` §SEM-REQ-004

#### 3.2.1 控制流→基本块

**输入：** `HirFunction`（含 `HirBlock` body，body 内可能嵌套 `HirStmt::If`/`HirStmt::For`/`HirStmt::While`/`HirStmt::Loop`）  
**输出：** `TirFunction`（含 `Vec<BasicBlock>`，控制流扁平化为基本块 + 跳转）

**降级算法：**

1. 创建入口基本块 `entry_block`。
2. 遍历 `HirBlock.statements`：
   - `HirStmt::Let` → `TirOp::Let` 或 `TirOp::Move`
   - `HirStmt::Expr(Expr)` → 表达式降级为 TIR 操作序列
   - `HirStmt::Return(v)` → 当前基本块终结指令设为 `Terminator::Return`
3. 遇到 `HirStmt::If`：
   - 分裂为 3 个基本块：`cond_block`、`then_block`、`else_block`（以及合并块 `join_block`）
   - `cond_block` 终结指令：`Terminator::If(cond_tmp, then_block_id, else_block_id)`
   - `then_block` / `else_block` 终结指令：`Terminator::Goto(join_block_id)`
4. 遇到 `HirStmt::For`：
   - 分裂为 `init_block` → `cond_block` → `body_block` → `update_block`，`cond_block` 条件跳转到 `body_block` 或出口 `exit_block`
5. 遇到 `HirStmt::While` / `HirStmt::Loop`：类似 for，生成条件块 + 循环体块 + 回边。

#### 3.2.2 表达式→语句

`HirExpr::If`（表达式）：`let x = if (c) { 1 } else { 0 };`
- 降级为基本块 split + 临时变量：
  - `then_block` 内最后一条：`TirOp::Let(tmp, IntLiteral(1))`
  - `else_block` 内最后一条：`TirOp::Let(tmp, IntLiteral(0))`
  - `join_block` 内第一条：`TirOp::Let(x_tmp, Var(tmp))`

`HirExpr::Loop`（表达式）：`let x = loop { break 42; };`
- `break` 语句带值 → 转换为 `TirOp::Let(loop_tmp, value)` + `Terminator::Goto(exit_block)`

`HirExpr::Block`：`let x = { let y = 1; y };`
- 块最后一条是表达式 → 将表达式值赋给临时变量，赋值给 `x_tmp`

#### 3.2.3 方法调用展开（占位）

Phase 1 无 struct/impl，方法调用不实现。保留展开函数签名：

```rust
/// §设计文档 §4.1: 方法调用展开（Phase 1 占位）
fn expand_method_call(_receiver: &HirExpr, _method: &str, _args: &[HirExpr]) -> TirOp {
    TirOp::Nop(Span::dummy())
}
```

#### 3.2.4 闭包捕获提升

**输入：** `HirExpr::ArrowFn { params, body, is_move }`  
**输出：** `TirFunction` + 捕获的外部变量列表

- 扫描 `body` 中引用的外部变量（变量名不在 `params` 和函数局部作用域内）
- 将外部变量加入 `captured_vars` 列表：
  - 默认闭包 → `BorrowKind::Shared`
  - `move` 闭包 → `BorrowKind::Mutable`（所有权转移——TIR 中以可变借用模拟 FnOnce 语义）
- 为每个捕获变量生成隐式参数（在闭包 body 的 TirFunction 参数列表中）

### 3.3 移动语义检查（`moveck.rs`，~250 行）

> 引用：`spec/trust-spec.md` §OWN-REQ-001, §OWN-REQ-008

#### 3.3.1 核心规则

```
MOVE-01: let b = a; → a 的所有权转移到 b，a 被标记为 "moved"
MOVE-02: 移动后访问 a → 错误 E0382（Use after move）
MOVE-03: Copy 类型不触发移动（标量 Copy、堆类型非 Copy）
MOVE-04: 函数参数 move x: T → 实参所有权移动到函数体
```

#### 3.3.2 Copy 类型判定表

| 类型 | Copy? | 说明 |
|------|-------|------|
| `i32`, `f64`, `i64` | ✅ | 标量类型，位拷贝安全 |
| `bool` | ✅ | 标量类型 |
| `&T` | ✅ | 引用类型是 Copy（共享借用） |
| `String` | ❌ | 堆分配 |
| `Vec<T>` / 数组 `T[]` | ❌ | 堆分配 |
| `bigint` | ✅ | 底层 i64，位拷贝 |
| 包含非 Copy 字段的复合类型 | ❌ | 逐字段判定 |
| `HirType::Error` | ❌ | 哨兵，保守处理 |

#### 3.3.3 错误信息映射（P0 约束）

```rust
// §design-constraints §6.2 / §8.3: TIR 内部名 → Trust 源码变量名 + 行列号
//
// 场景: tmp_3 (TIR 内部名) 被移动后使用
// 错误信息: "variable `data` moved at line 5, used at line 7"
// 映射表: TmpVar → (source_name: String, def_span: Span)
```

每个 `TmpVar` 在降级时记录其对应的 Trust 源码变量名和定义位置。错误报告时查询此表。

#### 3.3.4 公开接口

```rust

//

    E0384,  // cannot assign twice to immutable variable（函数参数 move 后赋值）

}
```

### 3.4 借用检查（`borrowck.rs`，~300 行）

> 引用：`spec/trust-spec.md` §OWN-REQ-002, §OWN-REQ-003, §OWN-REQ-004, §OWN-REQ-005

#### 3.4.1 三模式参数表（OWN-REQ-002）

| 声明 | 语义 | 调用处标注 | 缺失标注 |
|------|------|-----------|---------|
| `f(x: T)` | 只读借用 `&T` | `f(x)` | N/A |
| `f(inout x: T)` | 可变借用 `&mut T` | `f(inout x)` | `f(x)` → 错误 |
| `f(move x: T)` | 所有权转移 `T` | `f(move x)` | `f(x)` → 错误 |

**调用处检查算法：**
1. 解析函数声明 → 记录每个参数的 `ParamMode`
2. 解析调用处实参标注 → 记录每个实参的 `ParamMode`
3. 逐对比较：声明模式 vs 调用模式必须一致（Default=Default 无标注，InOut 需要 inout，Move 需要 move）
4. 不一致 → `BorrowError::MissingAnnotation`

#### 3.4.2 借用规则（Phase 1 词法作用域）（OWN-REQ-003）

```
BORROW-01: 同一变量同时 ≤1 可变借用
BORROW-02: 可变借用与只读借用不能共存
BORROW-03: 引用的生命周期不能超过被引用变量
BORROW-04: & 运算符创建显式引用
```

**Phase 1 简化：** 使用词法作用域（Lexical）而非完整 NLL（Non-Lexical Lifetimes 押后 Phase 3）。基本块内逐条扫描：
- 遇到 `TirOp::Borrow(tmp, src, Mutable)` → 检查 `src` 是否有活跃的共享借用或可变借用 → 有则报错；记录 `src` 的活跃可变借用
- 遇到 `TirOp::Borrow(tmp, src, Shared)` → 检查 `src` 是否有活跃的可变借用 → 有则报错；记录 `src` 的活跃共享借用
- 遇到 `TirOp::Move(tmp, src)` → 所有活跃借用必须已释放（Phase 1 词法：基本块边界释放）

#### 3.4.3 闭包捕获规则（OWN-REQ-005）

- 默认闭包 `() => expr`：只读借用外部变量 → `BorrowKind::Shared`
- `move` 闭包 `move () => expr`：所有权转移外部变量 → `BorrowKind::Mutable`（模拟 FnOnce）
- 捕获规则验证：默认闭包捕获的变量在其活跃借用期间不能有可变借用

#### 3.4.4 方法调用所有权（OWN-REQ-004 — Phase 1 占位）

Phase 1 无 struct/impl，此规则不执行检查。保留规则注释供 Phase 2 启用。

### 3.5 区域推断（Region Inference，~150 行）

> 引用：`spec/trust-spec.md` §OWN-REQ-007, §OWN-REQ-009

#### 3.5.1 生命周期自动推导（OWN-REQ-009）

| 场景 | 行为 |
|------|------|
| 函数返回非引用类型 | 无生命周期标注，编译通过 |
| 函数参数是 `&T`，返回值是 `&T` | 自动绑定返回值生命周期到参数 → 生成 `fn f<'a>(x: &'a T) -> &'a T` |
| 函数返回 `&T` 但无引用参数 | 推断不足 → 生成显式生命周期标注 `fn f<'a>() -> &'a T` 由 rustc 保底 |
| `for` 循环中 `let i = 0` | 隐式可变例外（OWN-REQ-007），不触发借用冲突 |

#### 3.5.2 for 循环隐式可变（OWN-REQ-007）

- `for (let i = 0; i < N; i = i + 1)` 中的 `i` **隐式可变**——唯一的 `let` 变量自动 `mut` 例外
- 检查规则：`i = i + 1` / `i = i + 1` 不产生"赋值给不可变变量"错误
- 非 for 循环上下文中的 `let` 变量不可变（AC-OWN-016）

#### 3.5.3 回退策略

如果 TIR 的区域推断无法确定某引用的生命周期来源，生成保守的显式 `'a` 标注 Rust 代码。rustc 作为第二道防线进行最终验证。这确保"静默正确"——宁可 rustc 报错，也不生成有悬垂指针的 Rust 代码。

## 6. 风险登记册

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| HIR 作用域信息不足以支撑 moveck | 中 | moveck 无法判定变量生死 | 依赖 Phase 1.3 的 `Scope` 结构，实现前验证 `HirBinding::LocalVar` 携带完整的 span + ty |
| 词法借用检查过于保守导致误报 | 高 | 合法借用被拒绝 | 提供清晰的错误信息 + 修复建议（如添加 `let mut`）；正式 NLL 押后 Phase 3 |
| Copy 判定与 Rust 标准库不一致 | 低 | 生成 Rust 代码后 rustc 二次报错 | 对齐 Rust 的 `Copy` trait 实现规则，标量/引用 → Copy，堆类型 → 非 Copy |
| 区域推断不足生成不完整 Rust 代码 | 中 | rustc 报错后用户困惑 | 回退策略：标注 `'a` 生成显式生命周期，rustc 错误信息包含 Trust 源码位置 |
| 闭包捕获提升后变量被双重计数 | 中 | 借用冲突误报 | 捕获变量仅计入闭包的 `captured_vars`，外层函数不再追踪其借用 |
| 临时变量名称与 Rust 保留字冲突 | 低 | rustc 拒绝编译 | TmpVar 生成名添加前缀 `trust_tmp_` |
| `for` 循环隐式可变例外范围过大 | 低 | 非 for 循环 `let` 误判为可变 | 仅在 `ForStmt` 的 init 中检查隐式可变标记 |

## 7. 边界条件检查清单

- [ ] 空函数体：`function f() {}` → `TirFunction { blocks: [entry], ops: [] }`
- [ ] 移动后使用：`let a = [1]; let b = a; let c = a;` → moveck 报 E0382（`a` 已移动）
- [ ] Copy 不触发移动：`let a = 42; let b = a; let c = a;` → moveck 不报错
- [ ] 只读借用 + 只读借用：`let r1 = &x; let r2 = &x;` → borrowck 不报错
- [ ] 可变借用 + 只读借用冲突：`let rm = &mut x; let r = &x;` → borrowck 报错
- [ ] `inout` 标注缺失：`function push(inout arr: number[]){} push(arr);` → borrowck 报错
- [ ] `move` 标注缺失：`function consume(move arr: number[]){} consume(arr);` → borrowck 报错
- [ ] `for` 隐式可变：`for (let i = 0; i < 10; i = i + 1) {}` → moveck 不报"赋值给不可变变量"
- [ ] 非 for 上下文中 `let` 不可变：`let x = 0; x = x + 1;` → moveck 报错
- [ ] 嵌套 `if` 表达式：`let x = if(a){if(b){1}else{0}}else{2}` → TIR 正确生成嵌套基本块 + 临时变量
- [ ] 闭包捕获默认借用：`let r = () => x;` → `x` 以 `Shared` 借用捕获
- [ ] 闭包捕获 move：`let c = move () => x;` → `x` 以 `Mutable` 借用捕获（FnOnce 模拟）
- [ ] 闭包内引用外部变量在捕获后仍使用：moveck 检测"捕获变量被移动后使用"
- [ ] 死代码（不可达基本块）：降级时标记 `Terminator::Unreachable`
