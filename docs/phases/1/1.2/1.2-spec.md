## 0. 文件说明

本规格书定义 **Phase 1.2**（`trust_parser` crate：词法分析 + 语法分析 → AST）的工程范围、成功标准、验收条件。

### 3.2 Lexer（词法分析器）（`lexer.rs`）

#### 3.2.1 Token 定义

```rust
#[derive(Debug, Clone, PartialEq)]
pub enum TokenKind {
    // 关键字（54 个，按 spec §LEX-REQ-001）
    Let, Mut, Const, Shared,
    Function, Fn,           // fn — lexer 无条件识别，parser 仅 extern 块内接受
    InOut, Move,
    Spawn, Async, Await, Select,
    If, Else, For, Of, While, Loop, Break, Continue, Return, Throw,
    Switch, Case, Default, Match,
    Import, Export, From, As,     // As: 既是关键字（类型转换）也是运算符（优先级表 12 级）
    Interface, Type, Impl, Extends, This, Dyn,
    Test, Extern,
    // 字面量值关键字
    True, False, Undefined, None_,
    Some_, Ok_, Err_,
    Rc, Arc, Weak, Box_,
    // 类型名关键字
    NumberType, StringType, BooleanType, BigIntType, VoidType,
    // 字面量值
    IntLiteral(i32), FloatLiteral(f64), BigIntLiteral(i64),
    StrLiteral(String),
    // 模板字符串 — 拆为三个 token，避免 lexer→parser 循环依赖
    TemplateHead(String),       // `hello, ${
    TemplateInterpolation,      // 插值分隔标记，parser 消费后递归 parse_expr()
    TemplateTail(String),       // } world` （最后一段，可能为空）
    // 运算符 / 分隔符
    Plus, Minus, Star, Slash, Percent,
    Eq, EqEq, Ne, Lt, Gt, Le, Ge,
    And, Or, Not,
    Amp,                // &
    Dot, DotDot,
    Colon, Semi, Comma,
    LParen, RParen, LBrace, RBrace, LBracket, RBracket,
    Arrow,              // =>
    Question, QuestionDot, QuestionQuestion,  // ?, ?., ??
    Bang,               // !
    // 特殊
    Ident(String),
    Comment(String),         // 注释 — 不传给 parser
    DocComment(String),      // /// 文档注释
    Eof,
}
```

#### 3.2.2 关键字识别策略

使用 `HashMap<&str, TokenKind>` 映射。优先级：关键字 > 类型名 > 标识符。

```rust
fn lex_ident(start: &str) -> TokenKind {
    match start {
        "let" => TokenKind::Let,
        "mut" => TokenKind::Mut,
        // ... 全部 40 个关键字 ...
        // 类型名
        "number" => TokenKind::NumberType,
        "string" => TokenKind::StringType,
        "boolean" => TokenKind::BooleanType,
        "bigint" => TokenKind::BigIntType,
        "void" => TokenKind::VoidType,
        // 字面量值
        "true" => TokenKind::True,
        "false" => TokenKind::False,
        // ...
        _ => TokenKind::Ident(start.to_string()),
    }
}
```

> **`fn` 关键字的上下文：** lexer 无条件将 `fn` 识别为 `TokenKind::Fn`，由 parser 在语法层面拒绝非 `extern` 块中的 `fn` 声明。

#### 3.2.3 字面量解析

| 格式 | 规则 | Token |
|------|------|-------|
| 整数 | `[0-9]+`（无 `.` 无 `n`） | `IntLiteral(i32)` |
| 浮点 | `[0-9]+ "." [0-9]+` | `FloatLiteral(f64)` |
| BigInt | `[0-9]+ "n"` | `BigIntLiteral(i64)` |
| 字符串 | `"..."` — 支持 `\"` `\\` `\n` 转义 | `StrLiteral(String)` |
| 模板 | `` ` ` `` ... `${` expr `}` ... `` ` ` `` — lexer 拆分 token，parser 组装 AST | `TemplateHead` / `TemplateInterpolation` / `TemplateTail` |

#### 3.2.4 注释处理

- `// ...` → 行尾停止 → `TokenKind::Comment`（不传给 parser）
- `/* ... */` → `*/` 停止，不可嵌套
- `/// ...` → `TokenKind::DocComment`（关联到 `export` 声明）

#### 3.2.5 运算符优先级表

15 级，Pratt parser 模式：

```rust
fn precedence(tok: &TokenKind) -> u8 {
    match tok {
        TokenKind::LParen | TokenKind::Dot => 15,
        TokenKind::Bang | TokenKind::Question => 14,
        TokenKind::Amp => 13,
        TokenKind::As => 12,
        TokenKind::Star | TokenKind::Slash | TokenKind::Percent => 11,
        TokenKind::Plus | TokenKind::Minus => 10,
        TokenKind::QuestionDot => 9,
        TokenKind::QuestionQuestion => 8,
        TokenKind::EqEq | TokenKind::Ne | TokenKind::Lt | TokenKind::Gt
            | TokenKind::Le | TokenKind::Ge => 7,
        TokenKind::And => 6,
        TokenKind::Or => 5,
        TokenKind::Eq | TokenKind::PlusEq | TokenKind::MinusEq
            | TokenKind::StarEq | TokenKind::SlashEq | TokenKind::PercentEq => 4,
        _ => 0,
    }
}
```

### 3.3 Parser（语法分析器）（`parser.rs`）

#### 3.3.1 解析器架构

**递归下降 + Pratt parser（表达式层）**：

```
parse_program()
  → parse_imports()
  → parse_exports()
  → parse_stmt() × N
       → parse_var_decl()      // let / let mut / const / shared
       → parse_function()      // function
       → parse_if()            // if / else
       → parse_for()           // for / for-of
       → parse_while()         // while
       → parse_loop()          // loop
       → parse_return()        // return
       → parse_break()         // break
       → parse_continue()      // continue
       → parse_expr_stmt()     // expression → parse_expr()
            → pratt_parse(0)   // Pratt parser for operators
                 → parse_primary()
                      → IntLiteral | StrLiteral | Ident | ...
                      → TemplateHead → parse_template_literal()
                      → &expr → Expr::Reference
                      → (expr) → 消耗括号不产生 AST 节点
```

**模板字面量解析**：`TemplateHead` token 触发 `parse_template_literal()`：
1. 收集 `TemplateHead` 的字符串片段
2. 遇到 `TemplateInterpolation` → 递归 `parse_expr()` 收集插值表达式
3. 遇到 `TemplateTail` → 收集尾部字符串 → 组装 `Expr::TemplateLiteral(Vec<TemplatePart>)`

#### 3.3.3 EBNF 产生式（Phase 1 子集）

```ebnf
var_decl    ::= ("let" | "let" "mut") ident (":" type)? "=" expr ";?"
              | "const" ident (":" type)? "=" expr ";?"
              | "shared" ident (":" type)? "=" expr ";?"

function_decl ::= "function" ident "(" param_list? ")" (":" type)? ("{" stmt* "}" | "=" expr ";")
param         ::= ("inout" | "move")? ident (":" type)?
param_list    ::= param ("," param)*

if_expr    ::= "if" "(" expr ")" block ("else" ("if" "(" expr ")" block | block))?
for_stmt   ::= "for" "(" ("let" ident "=" expr ";" expr ";" expr) ")" block
             | "for" "(" "let" ident "of" expr ")" block
while_stmt ::= "while" "(" expr ")" block
loop_expr  ::= "loop" block
return_stmt ::= "return" expr? ";?"
break_stmt ::= "break" expr? ";?"
continue_stmt ::= "continue" ";?"

import_decl ::= "import" (import_named | import_default | import_namespace) "from" string ";?"
import_named   ::= "{" ident ("," ident)* "}"
import_default ::= ident
import_namespace ::= "*" "as" ident
export_decl ::= "export" ("default")? (function_decl | var_decl)

arrow_fn ::= ("move")? "(" param_list? ")" "=>" expr
closure   ::= ("move")? "(" param_list? ")" "=>" block
template_literal ::= template_head (expr template_tail)* template_tail

expr ::= primary
       | expr op expr
       | "&" expr
       | expr "!"
       | expr "?"
       | expr "as" type
       | expr "??" expr
       | expr "?." ident

-- 辅助非终结符
block   ::= "{" stmt* "}"
stmt    ::= var_decl | const_decl | shared_decl | function_decl
         | if_expr | for_stmt | for_of_stmt | while_stmt | loop_expr
         | return_stmt | break_stmt | continue_stmt
         | import_decl | export_decl
         | expr_stmt
```

**换行分隔策略：** 词法器在换行处自动插入隐式分号（规则对齐 Go/TypeScript 的 ASI）。实现方式：遇到 `\n` 后检查前一个 token 是否能结束语句（如 `}`、`ident`、字面量、`)`、`]`），若能则插入 `Semi` token。`{` `(` `[` 等开启块/表达式的 token 阻止分号插入。

#### 3.3.4 调用处所有权标注

```ebnf
call_arg ::= ("inout" | "move")? expr
call_expr ::= expr "(" call_arg ("," call_arg)* ")"
```

parser 在调用处必须接受 `inout`/`move` 标注，否则报错（OWN-REQ-002 要求对称）。

#### 3.3.5 错误恢复

**Panic mode：** 遇到语法错误 → 生成 Diagnostic → 跳过 token 直到同步点 → 恢复解析。

**同步点：** `;` `}` `function` `import` `export` `type` `interface` `impl` `test` `async`

**验收标准：**
- AC-ERR-REC-001: 含语法错误的 `.trust` 文件产生 ≥2 个诊断信息（原 trust-spec SYN-REQ-013 AC-SYN-037，重编号为独立标准）
- AC-ERR-REC-002: 错误恢复后，后续合法代码产出正确的 AST 节点（原 trust-spec SYN-REQ-013 AC-SYN-038，重编号）

### 3.5 导入解析（`resolve_imports.rs`）

三种格式：

```ts
import { foo, bar } from "./util";

```

路径：`"./..."` → 相对路径；`"/..."` → 项目根；`"std::..."` → Phase 2+。

验收标准：
- AC-IMP-001: `import { add } from "./math";` → 解析路径 `./math.trust`
- AC-IMP-002: 未找到目标文件 → 报错
- AC-IMP-003: 导出不存在 → 报错
