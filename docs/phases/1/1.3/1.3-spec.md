## 0. 文件说明

本规格书定义 **Phase 1.3**（`trust_hir` crate：AST→HIR 降级 + 名称解析 + 类型检查 → 带类型标注的 HIR）的工程范围、成功标准、验收条件。

**背景：** `trust_hir` 是编译管线的第二站。它消费 `trust_parser` 产出的 AST，执行名称解析（将 `import { foo }` 绑定到实际文件的导出符号）、作用域构造，以及类型检查（验证操作数的类型兼容性）。输出是带类型标注的 HIR，供 `trust_tir`（Phase 1.4）做所有权检查。

**一句话成功：** `cargo test -p trust_hir` 全部通过，对于合法输入产出类型正确的 HIR，对于非法输入收集全部类型错误。

#### 3.1.4 表达式

> **降级策略：** AST→HIR 降级遵循以下映射——
> - `Expr::IfExpr` → `HirExpr::If(...)`（if 是表达式，AC-SEM-002）
> - `Expr::LoopExpr` → `HirExpr::Loop(...)`（loop 是表达式）
> - `Expr::BlockExpr` → `HirExpr::Block(...)`
> - `Expr::MemberAccess { object: Ident("console"), field: "log" }` → 降级时转换为 `HirExpr::Call(Ident("ferro_rt::console::log"), ...)`（Phase 1 唯一合法的 MemberAccess 路径；不支持任意对象字段访问）
> - `Expr::Null` → HIR 降级报错（Phase 1 未定义 null 语义，押后 Phase 3）
> - `Expr::Binary(_, QuestionQuestion, _)` → HIR 降级报错（`??` 押后 Phase 2）
> - `Expr::AssertUnwrap` / `Expr::TryPropagate` → 透传保留（Phase 1 仅解析，押后 Phase 3）

```rust
// Phase 1 降级：所有 AST Expr 映射到 HIR 对应变体
// 不含泛型/闭包推断/method resolve（Phase 2+）
pub enum HirExpr {
    /// 整数字面量 i32
    IntLiteral(i32, Span),
    /// 浮点字面量 f64
    FloatLiteral(f64, Span),
    /// BigInt 字面量 i64
    BigIntLiteral(i64, Span),
    /// 字符串字面量 String
    StringLiteral(String, Span),
    /// 布尔字面量 bool
    BoolLiteral(bool, Span),
    /// 模板字面量（已拼接为 String 或保留插值）
    TemplateLiteral(Vec<HirTemplatePart>, Span),
    /// 标识符引用（名称解析后填充 HirBinding；降级阶段用 Unresolved 占位）
    Ident(String, HirBinding, Span),
    /// 二元运算（左右操作数类型已检查）
    Binary(Box<HirExpr>, BinOp, Box<HirExpr>, HirType, Span),
    /// 一元运算
    Unary(UnaryOp, Box<HirExpr>, HirType, Span),
    /// 函数调用（实参类型已验证）
    Call(Box<HirExpr>, Vec<HirCallArg>, HirType, Span),
    /// 箭头函数（闭包）— Phase 1 参数需显式类型标注；bool = is_move
    ArrowFn(Vec<HirParam>, HirType, HirBlock, bool, Span),
    /// `as` 显式类型转换
    AsCast(Box<HirExpr>, HirType, Span),
    /// `&` 显式引用
    Reference(Box<HirExpr>, Span),
    /// `!` 断言 unwrap — Phase 1 仅 AST 解析，HIR 透传（押后 Phase 3）
    AssertUnwrap(Box<HirExpr>, Span),
    /// `?` Try 传播 — Phase 1 仅 AST 解析，HIR 透传（押后 Phase 3）
    TryPropagate(Box<HirExpr>, Span),
    /// `if` 表达式 — `let x = if (c) { 1 } else { 0 }` 降级产物（AC-SEM-002）
    If(HirIf, Span),
    /// `loop` 表达式 — `let x = loop { break 1; }` 降级产物
    Loop(HirLoop, Span),
    /// 块表达式 — `let x = { let y = 1; y }` 降级产物
    Block(HirBlock, Span),
    /// 哨兵：类型错误
    Error(Span),
}

pub struct HirTemplatePart {
    pub kind: HirTemplatePartKind,
    pub span: Span,
}

pub enum HirTemplatePartKind {
    String(String),
    Expr(Box<HirExpr>),
}

pub struct HirCallArg {
    pub mode: ParamMode,
    pub expr: Box<HirExpr>,
    pub span: Span,
}
```

### 3.2 名称解析（`name_res.rs`）

> 引用：`spec/trust-spec.md` §SEM-REQ-002

#### 3.2.1 跨文件 import 解析

**输入：** `trust_parser` 产出的 `Program`（含 `imports: Vec<ImportDecl>`）  
**输出：** `HirProgram`（含 `imports: Vec<HirImport>`，每个绑定了实际文件路径和符号）

**路径格式：** 四种（与 parser 对齐）

| 格式 | 示例 | 解析方式 |
|------|------|---------|
| `./` | `"type":" ./util"` | 当前目录相对路径 → `<cwd>/util.trust` |
| `../` | `"type":" ../lib"` | 上级目录相对路径 → `<cwd>/../lib.trust` |
| `/` | `"type":" /src/math"` | 项目根相对路径（以 `src/` 为 root） |
| `std::` | `"type":" std::console"` | 标准库路径（Phase 1 仅占位，Phase 2 启用） |

**导入语法：**

```rust
// Named: import { foo, bar } from "./util"
// Default: import defaultExport from "./mod"
// Namespace: import * as ns from "./lib"
```

**解析流程：**

1. 对每个 `ImportDecl`，根据路径格式定位目标文件
2. 调用 `trust_parser::module_graph` 的模块图加载目标文件的 AST
3. 在目标文件的 `exports` 中查找被导入的符号
4. 验证：导出存在 → 创建 `HirBinding::Import` 绑定；不存在 → `Diagnostic` 报错
5. 循环导入检测 → `Diagnostic` 报错（复用 parser 的 DAG 循环检测）

#### 3.2.2 作用域构造

对每个 HIR 项构建嵌套作用域：

| 声明 | 作用域级别 | 说明 |
|------|-----------|------|
| `const` | 模块作用域 | 编译时常量，整个模块可见 |
| `shared` | 模块作用域 | 模块级共享变量，Arc 包裹 |
| `function` 参数 | 函数局部作用域 | 参数名进入函数 body 作用域 |
| `let` / `let mut` | 块级作用域 | 最近的花括号 `{}` 内可见 |
| `import` 绑定 | 模块作用域 | 导入的符号对整个文件可见 |

**作用域链：** 查找符号时从最内层作用域向外搜索，直到模块作用域。未找到 → 编译错误。

#### 3.2.3 符号冲突检测

- 同一作用域内重复声明同名符号 → 编译错误
- `import` 符号与本地声明冲突 → 编译错误（不 shadow，直接报错）

### 3.3 类型检查（`typeck.rs`）

> 引用：`spec/trust-spec.md` §SEM-REQ-003, §TYP-REQ-001

#### 3.3.1 基本类型系统

Phase 1 的类型是所有 Phase 2 类型系统的**最简子集**：没有泛型、没有 interface、没有 ADT、没有 trait object。类型检查只关注两件事：

1. **二元运算的操作数类型一致性** — 核心规则：`i32 + f64` 报错
2. **函数调用实参与形参的数量和类型匹配**

#### 3.3.2 类型推断规则（Phase 1）

| 表达式 | 推断出的类型 | 说明 |
|--------|------------|------|
| `42`, `0`, `-7` | `HirType::I32` | 整数字面量 |
| `3.14`, `0.0` | `HirType::F64` | 浮点字面量 |
| `9007199254740991n` | `HirType::I64` | BigInt 字面量 |
| `"hello"` | `HirType::String` | 字符串字面量 |
| `true`, `false` | `HirType::Bool` | 布尔字面量 |
| `let x: number = 42` | `HirType::I32` | 类型标注覆盖字面量默认推断 |
| `let x: number = 3.14` | `HirType::F64` | 同上 |
| `let x: number;`（无 init） | `HirType::I32` | 无字面量上下文时默认 I32 |
| `function f(x: number)`（参数） | `HirType::I32` | 函数参数 `number` 默认 I32；若需 F64 使用 `as f64` 标注 |
| `let x: number = someVar`（变量 init） | 从 `someVar` 类型继承 | 右值类型决定左值类型 |
| `a + b`（a, b 均为 I32） | `HirType::I32` | 算术运算保持类型 |
| `a + b`（a, b 均为 F64） | `HirType::F64` | 同上 |
| `a as f64` | `HirType::F64` | `as` 显式转换 |
| `a < b`（比较运算） | `HirType::Bool` | 比较运算统一产出 Bool |
| `a == b`（相等比较） | `HirType::Bool` | 相等比较统一产出 Bool |
| `&x` | `HirType::Named(...)` 暂存 | Phase 1 仅推断引用类型，无完整生命周期 |
| 函数调用 `f(args)` | 函数声明返回类型 | 函数调用类型 = 声明的返回类型 |

#### 3.3.3 二元运算类型检查

**规则：**

```
TY-RULE-01（算术运算）：Add/Sub/Mul/Div/Mod
  - 左右操作数类型必须相同（均为 I32 或均为 F64）
  - I32 + I32 → I32, F64 + F64 → F64
  - I32 + F64 → TypeError

TY-RULE-02（比较运算）：Eq/NotEq/Lt/Gt/LtEq/GtEq
  - 左右操作数类型必须相同
  - 结果类型：Bool

TY-RULE-03（逻辑运算）：And/Or
  - 左右操作数必须均为 Bool
  - 结果类型：Bool

TY-RULE-04（字符串拼接）：Add（仅当左右均为 String 时）
  - String + String → String
  - 数字 → 字符串：禁止隐式转换，需显式 as 或调用 toString()
```

**检查函数：**

```rust
// §设计文档 §3.2.1 / spec TYP-REQ-001: 二元运算类型检查
//
// 注：接口示意——实际实现返回 thiserror 类型而非 ()。
pub fn check_binary_op(
    op: BinOp,
    lhs: &HirType,
    rhs: &HirType,
    span: Span,
    diagnostics: &mut Vec<Diagnostic>,
) -> Result<HirType, ()>;
```

#### 3.3.4 `as` 显式类型转换检查

| 源类型 | 目标类型 | 是否允许 |
|--------|---------|---------|
| I32 | F64 | ✅ 允许（精度无损） |
| F64 | I32 | ✅ 允许（截断，带 warning） |
| I32 | I64 | ✅ 允许 |
| I64 | I32 | ✅ 允许（截断，带 warning） |
| String | String | ✅ 允许（no-op） |
| Bool | I32 / F64 | ❌ 禁止 |
| 跨族转换 | — | ❌ 禁止 |

#### 3.3.5 函数签名验证

```rust
// §设计文档 §3.1.3 / spec SEM-REQ-003: 函数调用类型检查
pub fn check_call(
    func_name: &str,
    func_type: &HirType,        // HirType::Function(params, ret)
    args: &[HirCallArg],
    span: Span,
    diagnostics: &mut Vec<Diagnostic>,
) -> Result<HirType, ()>;
```

验证步骤：
1. 实参数量 = 形参数量（不等 → 报错）
2. 按位置逐对比较类型（实参类型 ≠ 形参类型 → 报错）
3. 返回类型 = 函数声明的返回类型

#### 3.3.6 哨兵类型（Type::Error）

```rust
// §design-constraints §3.1.1: 类型错误不停止检查，用哨兵填充
//
// 场景：let x = "hello"; let y = x + 1;
//   step 1: x 推断为 String
//   step 2: x + 1 → String + I32 → TypeError
//   step 3: y 的类型设为 HirType::Error（哨兵）
//   step 4: 后续引用 y 的表达式遇到 Error 类型时跳过检查（避免级联报错）
```

**规则：**
- 任何涉及 `HirType::Error` 作为操作数的表达式，不做进一步类型检查
- 但 ERROR 本身不计入诊断（诊断已在首次类型错误时生成）
- 这确保用户看到的是**根因**而非 n 条"y 的类型不匹配"级联错误

#### 3.3.7 公开接口

```rust
// §设计文档 §3.1.3 / spec SEM-REQ-003: 类型检查入口
pub fn check_types(
    hir: &mut HirProgram,
    diagnostics: &mut Vec<Diagnostic>,
) -> Result<(), Vec<Diagnostic>>;
```

检查策略（对齐 constraints §3.1.1）：
- **函数级独立：** 每个 `HirFunction` 独立 `check_function()`，错误收集进 `Vec<Diagnostic>`
- **单函数遇到不可恢复错误：** 用 `?` 提前终止该函数的检查（但不影响其他函数）
- **全部函数检查完毕：** `diagnostics.is_empty() ? Ok(()) : Err(diagnostics)`

---

### 3.4 错误收集策略（对齐 constraints §3.1.1）

```rust
// ✅ 正确 —— 函数级独立检查，收集所有错误后统一报告
pub fn check_module(hir: &mut HirProgram) -> Result<(), Vec<Diagnostic>> {
    let mut diagnostics = Vec::new();

    for item in &mut hir.items {
        match item {
            HirItem::Function(f) => {
                // 函数级独立：此函数的类型错误不阻止其他函数检查
                if let Err(errs) = check_function(f, &hir.scope) {
                    diagnostics.extend(errs);
                }
            }
            HirItem::Const(c) => { /* 常量检查 */ }
            HirItem::Shared(s) => { /* shared 检查 */ }
            HirItem::Stub(_) => {}  // 跳过占位项
        }
    }

    if diagnostics.is_empty() {
        Ok(())
    } else {
        Err(diagnostics)
    }
}
```

**错误信息格式：** 所有错误使用 `trust_error` crate 的 `Diagnostic` 结构体（Phase 1.6 定义，本阶段直接依赖）。

## 6. 风险登记册

| 风险 | 可能性 | 影响 | 缓解措施 |

## 7. 边界条件检查清单

- [x] 空文件：`""` → `HirProgram { items: [], ... }`（不 panic）
- [x] 空函数体：`function f() {}` → `HirFunction { body: HirBlock { stmts: [] } }`
- [x] 未解析的标识符：`let x = unknownVar;` → `Diagnostic`（名称解析报错）
- [x] 类型不匹配的嵌套表达式：`let x = (1 + "hello") + 3;` → 哨兵 `Error` 阻止 `+ 3` 二次报错
- [x] 函数调用参数数量不匹配：`add(1)` 少传 + `add(1, 2, 3)` 多传 → 两条独立 Diagnostic
- [x] 循环导入：`a.trust` import `b.trust` import `a.trust` → `Diagnostic`（复用 parser ModuleGraph 循环检测，AC-MOD-001）
- [x] import 不存在文件：`import { x } from "./nope"` → `Diagnostic`（resolve_import_path 解析路径，文件存在性检查在上层名称解析阶段完成）
- [x] import 不存在的导出：`import { noSuchExport } from "./real.trust"` → `Diagnostic`（名称解析阶段未找到导出符号 → undefined identifier 错误）
- [x] `as` 转换禁止组合：`true as f64` → `Diagnostic`；`"hi" as i32` → `Diagnostic`
- [x] 每个 `BinOp` 变体的类型组合矩阵（至少 Add/Sub/Mul/Div/Mod × {I32,F64}² + Eq × {I32,I64,F64,String,Bool}²）
