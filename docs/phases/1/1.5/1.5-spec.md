## 0. 文件说明

本规格书定义 **Phase 1.5**（`trust_codegen` crate：TIR → Rust 源码生成 + Source Map + ferro_rt API 映射）的工程范围、成功标准、验收条件。

**背景：** `trust_codegen` 是编译管线的第四站。它消费 `trust_tir` 产出的所有权注解完备的 TIR 控制流图，执行：

1. **TIR → Rust 源码生成（codegen.rs）**：将 TirProgram 中的每个 TirFunction 转换为 Rust `fn`；基本块转换为线性语句序列；条件跳转转换为 `if`/`else`；循环结构转换为 `loop`/`while`/`for`。
2. **参数模式映射**：TIR 的 `ParamMode::Default` → `&T`、`ParamMode::InOut` → `&mut T`、`ParamMode::Move` → `T`。
3. **Source Map（sourcemap.rs）**：记录每个 TIR 节点到生成 Rust 代码位置的映射，支持回退模式 `// @trust:` 注释。
4. **运行时库接口（runtime.rs）**：Trust 标准库调用（`console.log` 等）映射到 `ferro_rt` crate 的对应函数。

输出是可独立通过 `rustc` 编译的 Rust 源码文件。

**一句话成功：** 对于所有权正确的 TIR，codegen 生成可通过 `rustc` 编译的 Rust 源码；`cargo test -p trust_codegen` 全部通过；端到端 `console.log("Hello, Trust!")` 编译执行输出正确。

## 1. 成功标准

**MS-1.5-1（Rust 源码可编译）：** 对于所有权正确（moveck/borrowck 零错误）的 TIR，生成的 Rust 源码可通过 `rustc` 编译，不产生任何 rustc 错误（soundness by construction，constraints §7.1）。

**MS-1.5-2（参数模式正确映射）：** `Default` 参数生成 `&T`、`InOut` 生成 `&mut T`、`Move` 生成 `T`。函数签名中的生命周期标注（来自区域推断）正确映射为 Rust 生命周期参数。

**MS-1.5-3（控制流正确生成）：** TIR 的 `if`/`for`/`while`/`loop` → Rust 等价控制流。`if`/`loop` 表达式的临时变量正确降级为 Rust 局部变量。`break`/`continue` 正确映射。

**MS-1.5-4（Source Map + 运行时映射）：** 每个 TIR 节点 → Rust 位置的映射可查询。`console.log("...")` 生成 `ferro_rt::console::log("...")`。标准库路径通过 `use ferro_rt::...` 正确引入。

**MS-1.5-5（P0 约束遵守）：** 所有 Trust/Rust 语法字符串通过结构化方法生成，禁止硬编码（constraints §2.2 P0）。所有 pub 函数上方标注 `// §X.Y.Z:` 设计文档引用（constraints §1.3 P0）。所有字面量（除 0/1/公认常量）使用命名常量（constraints §2.1 P0）。零 `unwrap()`/`expect()`（使用 `?` 传播错误）。`trust_codegen` 中如有 `unsafe`（DWARF 写入），必须附带 `// SAFETY:` 注释（constraints §3.2）。

## 3. 详细规格

### 3.1 Rust 源码生成（`codegen.rs`，~400 行）

> 引用：`spec/trust-spec.md` §SEM-REQ-005（编译管线编排）、AC-SEM-010  
> 引用：`docs/design-constraints.md` §7.1（soundness by construction）、§2.2（禁止硬编码）

#### 3.1.0 核心原则

**Soundness by construction（constraints §7.1）：** 生成的 Rust 代码必须保证通过 rustc 检查。Codegen 不负责验证所有权正确性——该工作已在 `trust_tir` 完成。Codegen 的职责是**机械地**将已验证的 TIR 映射为语法正确的 Rust 代码。

**禁止硬编码（constraints §2.2）：** 所有 Trust/Rust 语法字符串（`"fn "`, `"let "`, `"&"`, `"->"` 等）必须定义为命名常量，通过结构化方法拼接。禁止 `format!("fn {}()", name)` 式的裸字符串。

#### 3.1.1 参数模式映射（§OWN-REQ-002 下游）

| TIR ParamMode | Rust 参数类型 | 示例 |
|---------------|--------------|------|
| `Default` | `&T` | `function f(x: number)` → `fn f(x: &i32)` |
| `InOut` | `&mut T` | `function f(inout x: number)` → `fn f(x: &mut i32)` |
| `Move` | `T` | `function f(move x: String)` → `fn f(x: String)` |

**生命周期参数映射（K13 fix）：** 如果 `TirFunction.lifetime_params` 非空（如 `["a"]`）：

1. 在函数签名中生成 `fn f<'a>(...)`。
2. **绑定规则**：遍历所有参数类型和返回类型中的 `&T`，将其替换为 `&'a T`。Phase 1 简化——`lifetime_params` 仅有一个元素时，所有 `&T` 统一使用该生命周期。多生命周期（如 `['a, 'b]`）押后 Phase 2。
3. 示例：
```rust
// TIR: lifetime_params = ["a"], params 中有 &T, return 为 &T
// 生成: fn f<'a>(x: &'a i32) -> &'a i32
```

**类型映射表：**

| Trust 类型 / HirType 变体 | Rust 类型 | 说明 |
|---------------------------|----------|------|
| `number`（整数）→ `HirType::I32` | `i32` | |
| `number`（浮点）→ `HirType::F64` | `f64` | K1 fix |
| `string` → `HirType::String` | `String` | |
| `boolean` → `HirType::Bool` | `bool` | |
| `void` → `HirType::Void` | `()` | |
| `bigint` → `HirType::BigInt` / `HirType::I64` | `i64` | |
| `T[]`（数组）→ `HirType::Array(T)` | `Vec<T>` | 递归映射元素类型 |
| `&T` → `HirType::Ref(T)` | `&T`（透传） | 递归映射内部类型。`&mut T` 通过 `ParamMode::InOut` 表达，不单独出现为 HirType |
| `HirType::Named(...)` | 原样使用类型名 | Phase 1 仅占位，Phase 2 启用 |
| `HirType::Function(...)` | `fn(...) -> ...` | Phase 1 仅占位 |
| `HirType::Error` | `()` | 哨兵，合法 TIR 不应出现 |

#### 3.1.2 函数生成

**输入：** `TirFunction`  
**输出：** Rust `fn` 声明 + 函数体

```
fn <name>[<lifetime_params>](<params...>) -> <return_type> {
    <body: 基本块序列>
}
```

**算法：**
1. 生成函数签名：`fn <name>(<params>) -> <return_type>`
2. 遍历 TirFunction 的 `blocks`，按控制流顺序生成 Rust 代码
3. 基本块内的 `ops` 逐条翻译为 Rust 语句
4. 终结指令翻译为控制流结构（见 §3.1.3）

**局部变量声明：** TIR 中的 `TmpVar` 需要映射为 Rust 局部变量。在基本块开头为活跃的 `TmpVar` 生成 `let mut` 声明（需要可变性分析——见 §3.1.4）。

**闭包捕获变量物化（K12 fix）：** 对于闭包 `TirFunction`，其 `params` 已包含捕获变量（降级阶段由 K5 生成）。Codegen 将 `params` 全部视为普通参数处理——
- 捕获变量的 `ParamMode` 由 `BorrowKind` 映射而来：`Shared → Default (&T)`、`Mutable → Move (T, FnOnce 语义)`
- 捕获变量名在闭包体内作为 Rust 局部变量可直接访问（不额外生成 `let`）

#### 3.1.3 控制流生成

**基本块 → Rust 控制流：**

```
Terminator::Goto(id)     → （内联后继块，或生成 goto 标签——Rust 无 goto，需要将基本块图重构为结构化控制流）
Terminator::If(cond, then, else) → if (cond) { <then块> } else { <else块> }
Terminator::Return(v)    → return <v>;
Terminator::Unreachable  → unreachable!();
```

**结构化控制流重构：** Rust 不支持 `goto`。codegen 需要将 TIR 的基本块 + 跳转图**重构**为 Rust 的结构化控制流（`if`/`else`、`loop`、`break`/`continue`）。

| TIR 结构 | Rust 生成策略 |
|----------|--------------|
| `If(cond, then_id, else_id)` + then → `Goto(join)` + else → `Goto(join)` | `if (cond) { <then> } else { <else> }` |
| `Goto(cond_id)` ... `cond_block: If(..., body, exit)` ... `body: ... Goto(cond)` | `loop { ... if (!cond) { break; } }` |
| `Goto(body_id)` ... `body: ... Goto(body_id)` ... `exit:` | `loop { <body> }` |
| for loop（init → cond → body → update → cond） | `for <init>; <cond>; <update> { <body> }` |
| `Goto(id)` 简单链（无回边） | 内联为顺序语句 |
| `break` → `Goto(exit_id)` | `break;`（若带值：`break <value>;`——仅 loop 表达式支持） |

**化简策略（Phase 1）：** 

1. **结构识别 passes：** 遍历基本块图，识别标准模式（if-then-else、loop、for）。按块 ID 的拓扑序生成代码。
2. **回边检测（K7 fix）：** 如果 `Goto` 的目标块 ID **≤** 当前块 ID，且目标块在当前循环上下文栈（`loop_stack`）中，视为循环回边，生成 `continue`。`≤` 覆盖 `loop { ... }` 的自循环场景（`Goto(body_id)` 目标 = 当前）。仅在 `loop_stack` 内才生成 `continue`，避免误判。
3. **break 检测：** 如果 `Goto` 的目标是循环出口块，生成 `break`。
4. **未识别模式回退：** 对于无法识别为结构化控制流的图，生成带标签的 `loop { ... break; }` 模拟（保守但正确）。

**Phase 1 已知限制：**
- 仅处理 Phase 1 TIR 产生的标准控制流模式（`lower_hir` 产出的 if/for/while/loop 结构）。
- 不可归约图（irreducible CFG）在 Phase 1 不会出现（TIR 降级总是产出可归约图）。

#### 3.1.4 TirOp → Rust 语句映射表

| TirOp | Rust 语句 | 示例 | 参数传递规则 |
|-------|----------|------|-----------|
| `Let(tmp, IntLiteral(v))` | `let _tN: i32 = v;` | `let _t0: i32 = 42;` | |
| `Let(tmp, FloatLiteral(v))` | `let _tN: f64 = v;` | `let _t0: f64 = 3.14;` | K2 fix |
| `Let(tmp, BigIntLiteral(v))` | `let _tN: i64 = v;` | `let _t0: i64 = 9223372036854775807;` | K2 fix |
| `Let(tmp, StringLiteral(s))` | `let _tN: String = s;` | — | |
| `Let(tmp, BoolLiteral(b))` | `let _tN: bool = b;` | — | |
| `Let(tmp, Var(src))`（Copy 类型） | `let _tN = src_var;` | `let _t1 = _t0;` | |
| `Let(tmp, Error)` | `let _tN = ();` | — | K2 fix：哨兵降级 |
| `Move(tmp, src)` | `let _tN = src_var;`（Rust 默认移动） | — | |
| `Borrow(tmp, src, Shared)` | `let _tN = &src_var;` | `let _r1 = &_t0;` | **源变量 `src_var` 不要求 `mut`** |
| `Borrow(tmp, src, Mutable)` | `let _tN = &mut src_var;` | — | **源变量 `src_var` 必须 `let mut`**（§3.1.4 可变性分析） |
| `Binary(tmp, lhs, op, rhs)` | `let _tN = lhs op rhs;` | `let _t2 = _t0 + _t1;` | |
| `Unary(tmp, op, val)` | `let _tN = op val;` | `let _t2 = -_t0;` | |
| `Call(dst, Function(name), args)` | `let _tN = name(&arg1, &mut arg2, arg3);` | `let _t3 = push(&_t0);` | **默认借用参数**传 `&arg`，**inout** 传 `&mut arg`，**move** 传 `arg`。K3 fix |
| `Call(dst, Function(name), args)`（闭包） | 同上，但闭包名 `$closure_N` 需重命名为合法 Rust 标识符（如添加 `_` 前缀） | — | K2 fix: `$` 不是合法 Rust 标识符 |
| `Call(dst, ...)`（非函数间接调用） | （Phase 1 不实现） | — | 函数指针/闭包变量调用押后 Phase 2 |
| `AsCast(tmp, val, ty)` | `let _tN = val as ty;` | `let _t2 = _t0 as i64;` | |
| `Nop` | （无输出） | — | |

**可变性分析（K4 fix）：** TIR 当前不在 `TmpVar` 中携带 mutability 元数据。Codegen 需通过**跨 op 扫描**确定哪些变量需要 `let mut`：

1. **多次赋值**：同一 `TmpVar` 在多个 `TirOp::Let`/`Move`/`Binary`/`Unary`/`Call` 中作为目标 → 标记 `mut`
2. **可变借用源**：`TirOp::Borrow(tmp, src, Mutable)` 的 `src` → 其对应的 Rust 变量必须 `let mut`
3. **InOut 实参源**：`TirArg { mode: InOut, value: Var(src) }` 的 `src` → 其对应的 Rust 变量必须 `let mut`
4. **for 更新变量**：`lower_for_stmt` 的 update 中赋值的变量 → 标记 `mut`（K10 fix）

**实现方式**：codegen 首遍扫描收集所有需要 `mut` 的 TmpVar 集合，二遍生成时在声明处使用 `let mut`。此方案纯 codegen 侧实现，不依赖 TIR 侧变更。

#### 3.1.5 `fn main()` 包装

Phase 1 隐式生成 `fn main()` 作为程序入口。规则：
- 如果 Trust 源码中定义了 `function main()`，直接映射为 Rust `fn main()`。
- 否则生成空 `fn main() {}`（仅用于编译通过，不产生输出）。
- `fn main()` 之前按需生成 `use ferro_rt::console;` 引入。**Phase 1 中 `console` 为隐式全局绑定**——即使 Trust 源码无显式 `import`，codegen 自动注入 `use`。若源码中有 `import { console } from "trust_std"`，name_res 处理符号绑定，codegen 不重复生成 `use`，避免冲突（K8 fix）。
- **多文件主入口（K20 fix）：** Phase 1 以单文件编译为主。若模块图中多个文件声明了 `function main()`，在 trustc 阶段报编译错误（"multiple main functions defined"），codegen 不做自动选择。

### 3.2 Source Map（`sourcemap.rs`，~120 行）

> 引用：constraints §7.2

#### 3.2.1 SourceMapping 结构体

```rust
/// Trust 源码位置 → 生成 Rust 源码位置 的双向映射
pub struct SourceMapping {
    /// (Trust行, Trust列) → (Rust行, Rust列)
    pub trust_to_rust: HashMap<(u32, u32), (u32, u32)>,
    /// (Rust行, Rust列) → (Trust文件, Trust行, Trust列)
    pub rust_to_trust: HashMap<(u32, u32), (String, u32, u32)>,
}
```

每条映射在 codegen 过程中插入——`emit_let(tmp, span)` 时记录 `span` 与当前 Rust 输出位置的对应关系。

**偏移跟踪机制（K14 fix）：** CodegenCtx 维护：
- `output: String` — Rust 源码缓冲区
- `current_line: u32` / `current_col: u32` — 当前输出位置（每 emit 一行后更新）
- `pending_mappings: Vec<(Span, u32, u32)>` — 待写入映射（span → 当前 line/col）

emit 函数在追加 Rust 代码前记录当前 (line, col)，追加后更新行列计数器。

**回退注释偏移补偿（K9 fix）：** 当插入 `// @trust:` 注释时，注释本身计入 `output` 并更新行列号。由于映射在 emit 前记录，注释插入不会破坏已有映射的准确性——后续映射自然使用注释后的新行列号。

#### 3.2.2 回退模式（v0.1）

当 Source Map 信息不足以精确定位时，在生成的 Rust 代码中插入注释：

```rust
// @trust: src/main.trust:42:15
let _t0 = 42;
```

此注释供调试器和错误报告使用，确保即使 Source Map 不完整，开发者仍能回溯到 Trust 源码。

## 6. 风险登记册

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| TIR 控制流图包含不可归约结构 | 低 | 结构化重构失败，生成不可编译的 Rust | Phase 1 TIR 降级只产生可归约图（if/for/while/loop）；对未识别模式回退到带标签的 `loop { break; }` |
| 类型映射遗漏导致 rustc 类型错误 | 中 | 生成代码不编译 | 完整的类型映射矩阵测试（§4.1）；每个 TirOp 变体至少 1 个快照测试 |
| **浮点/bigint 类型映射遗漏**（K16） | 中 | `f64`/`i64` 字面量生成错误类型 | §3.1.1 已完成 FloatLiteral/BigIntLiteral 映射；单元测试覆盖 |
| 可变性分析错误（`let` vs `let mut`） | 中 | rustc 报"cannot assign to immutable variable" | 首遍扫描收集 mut 集合（见 §3.1.4 K4 fix）；`Borrow(Mutable)`/`InOut` 源变量 + 多次赋值 + for 更新变量均标记 |
| Source Map 偏移计算错误 | 低 | 调试信息指向错误位置 | CodegenCtx 维护行列计数器（见 §3.2 K14 fix）；回退注释始终生成 |
| **Source Map 键冲突**（K16） | 低 | 多个 TIR 节点共享同一 Trust 源码位置时映射覆盖 | 使用 `(span, tmp_var_id)` 复合键，或对同位置的多次 emit 记录 first-write-wins |
| 闭包 TIR 函数未生成（name_res 提升问题） | 中 | 包含闭包的 Trust 程序 codegen 失败 | 本规格明确闭包生成为 Phase 2 完整实现；Phase 1 的闭包 codegen 依赖 name_res 行为（见已知限制） |
| 生成的 Rust 代码中使用保留字作为变量名 | 低 | rustc 拒绝编译 | TmpVar 生成名添加前缀 `_t` + 保留字检查 |
| `console.log` 参数类型不匹配 | 低 | rustc 类型错误 | Phase 1 仅支持字符串参数；非字符串参数生成 `&format!("{}", expr)` |
| **`TirValue::Error` 落入 codegen**（K16） | 低 | 生成残缺 Rust 代码 | `Error` 哨兵映射为 `()`，降级为 `let _tN = ();`；合法 TIR 不应出现 |
| `fn main()` 签名冲突（Trust 源码含自定义 `main`） | 低 | 重复定义 | 若 Trust 源码定义了 `function main()`，映射为 Rust `fn main()`；不额外生成包装 |
| **多文件项目多个 `function main()`**（K16） | 低 | 重复符号错误 | Phase 1 单文件为主；多文件时若多个 main 函数报编译错误（在 trustc 阶段检测） |
