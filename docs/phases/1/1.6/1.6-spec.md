## 0. 文件说明

本规格书定义 **Phase 1.6**（`trust_error` crate：统一错误诊断数据结构 + JSON 格式化输出 + 修复建议引擎）的工程范围、成功标准、验收条件。

**背景：** `trust_error` 是 Phase 1 的**基础 crate**——零依赖，被 parser / HIR / TIR / codegen / trustc 全部其他 crate 共用。它不实现任何编译逻辑，只提供：

1. **统一的 `Diagnostic` 结构体**：携带错误码、严重级别、多 span、修复建议。
2. **JSON 格式化输出**：支持 `--error-format=json`，对齐 LSP/IDE。
3. **修复建议引擎**：对常见错误（缺 `.clone()`、缺 `inout`、缺 `mut`）生成修复建议。

**依赖策略（D1 fix）：** 保持零外部依赖，**不引入 `serde`/`serde_json`**。所有类型手动实现 `Display` 和 JSON 序列化。

**一句话成功：** `trust_error` 提供 `Diagnostic` 结构体；`--error-format=json` 输出符合 spec schema；`--fix` 对 ≥3 种常见错误生成修复建议。

## 1. 成功标准

**MS-1.6-1（统一错误数据结构）：** `Diagnostic` 结构体包含 `ErrorCode` 枚举（覆盖 parser/HIR/TIR/codegen 全部已知错误码，含 parser 语法错误 + 模块系统错误，共 17 变体，E4 fix）、三级严重度（`Error`/`Warning`/`Help`）、多 span 支持（如移动处 + 使用处）、可选 children（修复建议）。

**MS-1.6-2（JSON 格式输出）：** `--error-format=json` 输出符合 spec 定义的 schema（constraints §8.2）。每条 Diagnostic 序列化为独立 JSON 对象，包含 `code`、`level`、`message`、`spans`、`children`。字段名对齐 constraints §8.2 + 设计文档 §9.1.1（D2 fix）。

**MS-1.6-3（修复建议引擎）：** `--fix` 模式对 ≥3 种常见错误（缺 `.clone()`、缺 `inout` 标注、缺 `mut`）生成修复建议。默认不自动应用——需用户交互确认。建议为启发式，不保证 100% 正确。

**MS-1.6-4（P0 约束遵守）：** 零 `unwrap()`/`expect()`。所有 pub 函数上方标注 `// §X.Y.Z:` 设计文档引用（constraints §1.3 P0）。零 `unsafe`。零外部依赖。

### 3.1 Diagnostic 结构体（`diagnostic.rs`，~150 行）

#### 3.1.1 Severity 枚举

```rust
// §8.1: 诊断严重级别（D1 fix: 去掉 Serialize，手动序列化）
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Severity {
    Error,   // 编译错误——阻止 codegen
    Warning, // 编译警告——不阻止 codegen
    Help,    // 帮助信息——附属于 Error/Warning
}
```

#### 3.1.2 ErrorCode 枚举（D3 fix: 补充 parser/模块错误码）

```rust
// §8.1: 错误码 —— 对齐 Rust 编译器错误码惯例
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ErrorCode {
    // === parser 语法错误 ===
    E0001, // 非法 token / unexpected token
    E0002, // 语句未闭合（缺 `;` / `}`）

    // === 模块系统 ===
    E0601, // 文件未找到
    E0602, // 循环导入
    E0603, // 导入目标不存在

    // === 移动语义 (moveck) ===
    E0382, // 移动后使用（use after move）
    E0384, // 不可变变量赋值（cannot assign twice to immutable variable）
    E0389, // 不可变变量赋值（cannot assign to immutable variable）

    // === 借用检查 (borrowck) ===
    E0501, // 可变借用冲突
    E0502, // 共享借用与可变借用冲突
    E0506, // 移动被借用的值

    // === 类型检查 (typeck) ===
    E0308, // 类型不匹配
    E0061, // 参数数量不匹配

    // === 语法/语义 ===
    E0425, // 未定义变量/函数
    E0428, // 重复定义
    E0700, // 无效的 `inout`/`move` 标注（含调用处缺失）

    // === 通用 ===
    E9999, // 内部编译器错误（ICE）
}
```

#### 3.1.3 SourceSpan 结构体

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct SourceSpan {
    pub file: String,           // 文件路径
    pub line_start: u32,        // 起始行（1-based）
    pub col_start: u32,         // 起始列（1-based）
    pub line_end: u32,          // 结束行（1-based）
    pub col_end: u32,           // 结束列（1-based）
    pub label: Option<String>,  // 可选标签
}
```

#### 3.1.4 FixSuggestion 结构体

```rust
// §8.4: 修复建议
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct FixSuggestion {
    pub message: String,     // 人类可读的修复描述
    pub span: SourceSpan,    // 需要替换的 span
    pub replacement: String, // 替换文本

```

#### 3.1.5 Diagnostic 结构体

```rust
// §8.1: 统一诊断结构体
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Diagnostic {
    pub code: ErrorCode,                      // 错误码
    pub level: Severity,                      // 严重级别（D2 fix: severity→level）
    pub message: String,                      // 人类可读的错误信息
    pub primary_span: SourceSpan,             // 主 span
    pub secondary_spans: Vec<SourceSpan>,     // 辅助 span（如 "moved here" + "used here"）
    pub fix_suggestions: Vec<FixSuggestion>,  // 修复建议（D2 fix: suggestions→fix_suggestions）
    pub children: Vec<Diagnostic>,            // 子诊断
}

impl Diagnostic {
    // §8.1: 创建简单错误
    pub fn error(code: ErrorCode, message: impl Into<String>, span: SourceSpan) -> Self;

    // §8.1: 创建带辅助 span 的错误
    pub fn error_with_secondary(
        code: ErrorCode, message: impl Into<String>,
        primary: SourceSpan, secondary: Vec<SourceSpan>,
    ) -> Self;

    // §8.1: 创建警告
    pub fn warning(code: ErrorCode, message: impl Into<String>, span: SourceSpan) -> Self;

    // §8.1: 创建帮助信息（D12 fix: 补充 Help 构造器）
    pub fn help(message: impl Into<String>, span: SourceSpan) -> Self;

    // §8.1: 添加修复建议
    pub fn with_suggestion(mut self, suggestion: FixSuggestion) -> Self;

    // §8.1: 添加子诊断
    pub fn with_child(mut self, child: Diagnostic) -> Self;
}
```

**spans 数组顺序（D17 fix）：** JSON 输出中 `spans` 数组的第一项始终为 `primary_span`，后续项为 `secondary_spans` 按添加顺序排列。`fix_suggestions`/`children` 为空时输出 `[]`（空数组）。

#### 3.1.6 Span 转换适配（D5 fix: 仅定义字段契约）

各编译阶段已有各自的 Span 类型。**转换在调用方实现**——`trust_error` 零依赖，不引用 `trust_parser` 或 `trust_tir`。调用方通过构造 `SourceSpan` 的字段传入：

```rust
// 调用方示例（parser crate 内部）：
let diag_span = SourceSpan {
    file: parser_span.file.clone(),
    line_start: parser_span.line_start,
    col_start: parser_span.col_start,
    line_end: parser_span.line_end,
    col_end: parser_span.col_end,
    label: Some("unexpected token".into()),
};
```

#### 3.1.7 JSON 序列化——Display trait

```rust
// §8.2: Severity 手动序列化（D6 fix: 明确映射）
impl std::fmt::Display for Severity {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            Severity::Error => write!(f, "\"error\""),
            Severity::Warning => write!(f, "\"warning\""),
            Severity::Help => write!(f, "\"help\""),
        }
    }
}

// ErrorCode 序列化
impl std::fmt::Display for ErrorCode {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "\"{:?}\"", self) // "E0382" 等
    }
}
```

### 3.2 JSON 格式化输出（`json_fmt.rs`，~80 行）

> 引用：constraints §8.2, §9.1.1

#### 3.2.1 JSON Schema（D2 fix: 字段名对齐 constraints §8.2）

```json
{
  "code": "E0382",
  "level": "error",
  "message": "use of moved value `x`",
  "spans": [
    { "file": "main.trust", "line_start": 3, "col_start": 5, "line_end": 3, "col_end": 6, "label": "value moved here" },
    { "file": "main.trust", "line_start": 5, "col_start": 5, "line_end": 5, "col_end": 6, "label": "used here after move" }
  ],
  "children": [],
  "fix_suggestions": [
    { "message": "consider cloning `x` before move", "span": { ... }, "replacement": "x.clone()" }
  ]
}
```

#### 3.2.2 序列化接口

```rust
// §9.1.1 / constraints §8.2: JSON 格式化
//
// ```
// # use trust_error::diagnostic::{Diagnostic, ErrorCode, Severity, SourceSpan};
// # use trust_error::json_fmt::format_diagnostics;
// let span = SourceSpan { file: "test.trust".into(), line_start: 1, col_start: 1, line_end: 1, col_end: 5, label: None };
// let diag = Diagnostic::error(ErrorCode::E0382, "use after move", span);
// let json = format_diagnostics(&[diag], /* pretty */ true);
// assert!(json.contains("\"E0382\""));
// ```
pub fn format_diagnostics(diagnostics: &[Diagnostic], pretty: bool) -> String;
```

**Phase 1 简化：** 手动构造 JSON 字符串。每个 Diagnostic 输出为独立 JSON 行（NDJSON 格式，`\n` 分隔）。空输入返回 `""`（D10 fix）。

**JSON 字符串转义规则（D14 fix）：** `message`、`replacement`、`file`、`label` 字段在序列化时需转义：`"` → `\"`、`\` → `\\`、换行 → `\n`。其他控制字符（`\t`、`\r`）同步转义。

### 3.3 修复建议引擎（`fix_suggest.rs`，~100 行）

> 引用：constraints §8.4

#### 3.3.1 检测规则（Phase 1，≥3 种）

| 规则 | 触发条件 | ErrorCode | 修复建议 |
|------|---------|-----------|---------|
| 缺 `.clone()` | 非 Copy 类型移动后继续使用 | E0382 | 在使用处前插入 `let x = x.clone();` |
| 缺 `inout` 标注 | 调用处实参与形参 InOut 不匹配 | E0700 (D8 fix) | 调用处添加 `inout` 标注 |
| 缺 `mut` | 对 `let` 变量赋值或可变借用 | E0389 | 将 `let x` 改为 `let mut x` |

#### 3.3.2 FixSuggestion 生成

```rust
// §8.4: 修复建议引擎入口
//
// 注意（D13 fix）：函数仅凭 Diagnostic 信号做启发式匹配，不保证建议 100% 正确。
// 准确修复需编译器上下文（类型是否 Clone、变量声明位置等）——押后 Phase 2 增强。
pub fn suggest_fixes(diagnostic: &Diagnostic) -> Vec<FixSuggestion>;
```

#### 3.3.3 交互式确认

`--fix` 模式下，trustc 遍历所有 `FixSuggestion`，逐条提示用户：

```
error[E0389]: cannot assign to immutable variable `x`
  → src/main.trust:3:5
help: consider making `x` mutable
  → let mut x = 42;
应用此修复？(y/N):
```

**Phase 1 限制：** 交互通过 `stdin`/`stdout` 实现。默认 `N`（不应用）。

## 6. 风险登记册

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| ErrorCode 与各阶段实际错误码不同步 | 中 | Diagnostic 构造错误 | 各阶段添加映射测试 |
| 手动 JSON 序列化格式错误 | 低 | IDE/LSP 解析失败 | 快照测试覆盖；字符串转义规则已定义（D14） |
| SourceSpan 跨阶段转换丢失行列信息 | 中 | 错误定位不准 | 各阶段 Span→SourceSpan 转换添加单元测试 |
| 修复建议不准确 | 中 | 用户应用后引入新错误 | 标注为启发式（D13）；`--fix` 默认不自动应用 |
| 零依赖约束限制功能 | 低 | JSON 格式不对齐 serde 标准 | Phase 2 评估引入 serde（§8 承接） |
| 迁移工作量超预期 | 低 | 多个 crate 需要改动 | 渐进迁移，提供 `From` trait 兼容包装 |
