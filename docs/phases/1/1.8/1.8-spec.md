## 3. 详细规格

### 3.1 TIR 所有权修复（`borrowck.rs` 局部修改，~50 行变更）

> 引用：constraints §6.2（区域推断）；1.7 spec §8 下沉项 F2–F5
> 背景：当前 Lexical 所有权模型对每个基本块独立检查借用，导致 for/while/loop 循环体中的借用被误报为冲突。

#### 3.1.1 问题诊断

| 场景 | 当前行为 | 根因 | 目标行为 |
|------|---------|------|---------|
| **for 循环** `for (let i=0; i<3; i=i+1) { ... }` | `i=i+1` 被 borrowck 拦截（不可变变量赋值） | Lexical 模型未识别 for 循环变量隐式可变例外（OWN-REQ-007） | `i` 在循环体内视为 `mut`，允许赋值 |
| **while 循环** `while (x>0) { x=x-1; }` | `x` 被 borrowck 拦截（不可变变量赋值） | while 体中 `x` 需要可变性，但 `let x = 3` 不提供 mut | `x` 需要 `let mut` 声明或 borrowck 识别循环体内赋值意图 |
| **loop + break** | 循环体借用检查在跨迭代时误报冲突 | 跨迭代借用未正确重置 | loop 每次迭代独立检查 |
| **break 带值** `let x = loop { break 42; };` | loop 表达式赋值给 `x` 时 moveck 误报 | loop 表达式值的所有权转移未正确处理 | `break 42` 的值正确转移给 `x` |

#### 3.1.2 修复策略

**修复 A：for 循环隐式可变（OWN-REQ-007 落地）**

在 `borrowck` 中识别 for 循环结构：当检测到变量在 for 循环的 update 子句（`i=i+1`）中被赋值时，将该变量在循环体内标记为隐式可变。修改 borrowck 的 `check_block` 函数，在进入 for 循环体前放宽对该变量的可变性约束。

```rust
// §OWN-REQ-007: for 循环变量隐式可变例外
// 在 check_function 遍历基本块时，识别 for 循环模式：
//   init: let i = 0 → cond: i < N → body → update: i = i + 1 → cond
// 将 i 标记为 for_loop_mutable，在循环体内允许 &mut 借用。
fn check_for_loop_body(&mut self, loop_var: VarId, body_blocks: &[BlockId]) -> Result<(), BorrowError> {
    let saved = self.mutable_vars.insert(loop_var);
    let result = self.check_blocks(body_blocks);
    if !saved {
        self.mutable_vars.remove(&loop_var);
    }
    result
}
```

**修复 B：while 循环体借用区域扩展**

while 循环的条件检查和循环体在同一个借用上下文中。当前 Lexical 模型按基本块独立检查，导致循环体中对条件变量的借用（`x = x - 1`）被误判。修复：while 循环的 condition block + body blocks 共享同一个 `BorrowContext`。

```rust
// §OWN-REQ-007 扩展: while 循环中条件块和循环体共享借用上下文
// while (x > 0) { x = x - 1; } 中，条件读取 x 和循环体写入 x 
// 需要 borrowck 理解"先读后写"在跨迭代中合法。
fn check_while_loop(&mut self, cond_block: BlockId, body_blocks: &[BlockId], exit_block: BlockId) -> Result<(), BorrowError> {
    // 策略：每次迭代独立检查借用。进入新迭代时重置借用状态。
    // Phase 1 简化：不建模跨迭代借用（保守拒绝以下模式：
    //   let r = &x; while ... { use(r); x = ...; } // 应拒绝，正确）
    //   while ... { let r = &x; use(r); x = ...; } // 应允许，Phase 1 保守拒绝 → Phase 2
    self.check_block(cond_block)?;
    for &block_id in body_blocks {
        self.check_block(block_id)?;
    }
    // 回边：重置借用状态
    self.reset_borrows_for_loop_backedge();
    Ok(())
}
```

**修复 C：loop 表达式所有权转移**

`let x = loop { break 42; };` 中，`break 42` 的值的所有权需要转移给 `x`。TIR 降级阶段（`lower_hir`）已经将 loop 表达式的值通过临时变量持有，borrowck/moveck 只需正确识别该临时变量的所有权转移路径。

```rust
// §OWN-REQ-001 扩展: loop 表达式 break 值的所有权转移
// TIR 中 loop { break <val>; } 的出口块包含 Move(val, loop_result_tmp)
// moveck 应将 loop_result_tmp 标记为已初始化，允许后续 move 到 let 绑定。
```

#### 3.1.3 修复优先级与回退策略

| 修复 | 优先级 | 回退策略 |
|------|--------|---------|
| A: for 隐式可变 | P0（阻塞 F2） | 若 borrowck 修改风险高，可在 parser 层将 for 循环变量默认设为 `mut` |
| B: while 借用上下文 | P0（阻塞 F3） | 要求用户显式 `let mut x = 3;`（修改测试夹具适配，但不阻塞交付） |
| C: loop 表达式所有权 | P0（阻塞 F5） | 若 moveck 修改复杂，可将 F5 降级为"loop break 语法正确 + TIR 生成正确"（不验证运行时值），押后 Phase 2 |
| D: loop + break 借用 | P1（F4 已有简单场景通过） | 当前 `loop { break; }` 已不触发 borrowck，仅复杂嵌套场景可能触发 |

### 3.2 Parser bigint 修复（`lexer.rs` 局部修改，~20 行变更）

> 引用：1.7 spec §8 下沉项 F1
> 背景：`tests/fixtures/bigint.trust` (`let x = 9223372036854775807;`) 在 1.7 被标注为 SKIP。

**诊断：** 检查 lexer 对 `9223372036854775807`（超出 `i32::MAX` 但属于 `i64` 范围）的解析。

**目标：** 
- 整数字面量在 `i32` 范围（`-2_147_483_648..=2_147_483_647`）内 → 解析为 `Token::IntLiteral(i32)`
- 整数字面量超出 `i32` 但属于 `i64` 范围 → 解析为 `Token::BigIntLiteral(i64)`
- 显式 `n` 后缀（如 `42n`）→ 强制 `BigIntLiteral`

**修复位置：** `crates/trust_parser/src/lexer.rs` 的 `read_number()` 方法。

```rust
// §LEX-REQ-004: bigint 字面量解析规则
// 1. 尝试解析为 i32（使用 parse::<i32>()）
// 2. 若溢出，尝试解析为 i64（使用 parse::<i64>()）
// 3. 若仍溢出或显式 `n` 后缀，报错或标记为 BigInt 溢出
fn finish_number(&mut self, start: usize, has_n_suffix: bool) -> Token {
    let s = &self.source[start..self.pos];
    let num_str = if has_n_suffix { &s[..s.len()-1] } else { s };
    
    if let Ok(v) = num_str.parse::<i32>() {
        if has_n_suffix { Token::BigIntLiteral(v as i64) }
        else { Token::IntLiteral(v) }
    } else if let Ok(v) = num_str.parse::<i64>() {
        Token::BigIntLiteral(v)
    } else {
        // 溢出 i64 → 诊断错误
        Token::Error(format!("integer literal too large: {}", num_str))
    }
}
```

/// 用法: assert_trust_output!("let_variable", "let ok");
macro_rules! assert_trust_output {
    ($fixture:expr, $expected:expr) => {{
        let path = format!("tests/fixtures/{}.trust", $fixture);
        let output_path = format!("/tmp/trust_test_{}", $fixture);
        
        let compile = Command::new(env!("CARGO_BIN_EXE_trustc"))
            .args(["compile", &path, "-o", &output_path])
            .output()
            .expect("trustc should run");
        
        assert!(
            compile.status.success(),
            "compile {} failed:\n{}",
            $fixture,
            String::from_utf8_lossy(&compile.stderr)
        );
        
        let run = Command::new(&output_path)
            .output()
            .expect("compiled binary should run");
        
        let stdout = String::from_utf8_lossy(&run.stdout);
        assert!(
            stdout.contains($expected),
            "{}: expected output containing '{}', got: '{}'",
            $fixture, $expected, stdout.trim()
        );
    }};
}

/// 编译 Trust 文件，仅验证编译通过（不验证运行时输出）
macro_rules! assert_trust_compiles {
    ($fixture:expr) => {{
        let path = format!("tests/fixtures/{}.trust", $fixture);
        let output_path = format!("/tmp/trust_test_{}", $fixture);
        
        let compile = Command::new(env!("CARGO_BIN_EXE_trustc"))
            .args(["compile", &path, "-o", &output_path])
            .output()
            .expect("trustc should run");
        
        assert!(
            compile.status.success(),
            "compile {} failed:\n{}",
            $fixture,
            String::from_utf8_lossy(&compile.stderr)
        );
    }};
}
