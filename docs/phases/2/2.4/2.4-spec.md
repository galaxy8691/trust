## 0. 文件说明

本规格书定义 **Phase 2.4**（承接 Phase 1 遗留项：`&mut x` 可变引用 + 闭包调用 `r()` + JSON→serde 迁移评估）的工程范围、成功标准、验收条件。

**延期项登记：** 本里程碑中归后续 Phase 的工作见 [`docs/phases/DEFERRED-AND-HANDOFFS.md`](../../DEFERRED-AND-HANDOFFS.md)。

**背景：** Phase 1 交付时留下了三个未闭环的能力——`&mut x` 可变引用（#7）、闭包调用 `r()`（#8）、JSON→serde 迁移评估（#10）。这三项是 ROADMAP Phase 2 交付标准的强制要求。

| #8 闭包调用 `r()` | ❌ `infer_type_from_expr` 对 `HirExpr::ArrowFn` 落入 `_ => HirType::Error`；`let f = …` 绑定为 `Error` → `Call` 报 `cannot call value of type` | ✅ Let 绑定 `HirType::Function` + e2e `f(5)` |

> **borrowck 注记：** `trust_tir::borrowck` **已有** `ActiveBorrow::Shared/Mutable` 与冲突规则（`&mut` 遇任何活跃借用、`&` 遇活跃可变借用均报错）。2.4 缺口在 parser/HIR/TIR **发射** `BorrowKind::Mutable`，而非重写 borrowck 框架。

**一句话成功：** `let mut x = 1; let r = &mut x; *r = 2;` 编译通过；`let f = (x: number) => x + 1; f(5)` 编译通过；`docs/phases/2/2.4/serde-evaluation.md` 产出决策文档。

## 1. 成功标准

### MS-2.4-1（`&mut x` 解析 → AST 节点）

**条件：** parser 支持 `&mut x` 语法，产出 `Expr::RefMut(Box<Expr>)`。

**验证：**
```bash
cargo test -p trust_parser -- snap_ref_mut   # Step 3 新增
```

### MS-2.4-2（`&mut x` HIR/TIR 降级）

**条件：** `name_res::lower_expr`：`Expr::RefMut` → `HirExpr::RefMut`（**推荐**独立变体，与 `HirExpr::Reference` 区分）。`trust_tir::lower_expr`：`HirExpr::RefMut` → `TirOp::Borrow(_, src, BorrowKind::Mutable, _)`；`HirExpr::Reference` 保持 `BorrowKind::Shared`。

**验证：**
```bash
grep -n 'RefMut\|BorrowKind::Mutable' crates/trust_hir/src/name_res.rs crates/trust_tir/src/tir.rs
```

### MS-2.4-3（TIR borrowck：`&mut` 冲突检查）

**条件：** 在 TIR 已发射正确 `BorrowKind` 的前提下，`check_borrows`（**现有实现**）在以下场景报错：
- 同一变量已有活跃只读借用时申请 `&mut` → 编译错误
- 同一变量已有活跃可变借用时再次 `&mut` → 编译错误
- 同一变量已有活跃可变借用时申请只读 `&` → 编译错误

**合法场景：**
- `let mut x = 1; let r = &mut x; *r = 2;` → 通过（独占可变借用）
- `let x = 1; let r1 = &x; let r2 = &x;` → 通过（多个只读借用）
- `let mut x = 1; { let r = &mut x; *r = 2; } let r2 = &x;` → 通过（`&mut` 作用域结束后只读借用）

**验证：**
```bash
cargo test -p trust_tir -- borrowck_ref_mut_ok
cargo test -p trust_tir -- borrowck_ref_mut_conflict
cargo test -p trust_tir -- borrowck_mut_ref_conflict
# 可选 e2e：trustc fixture ref_mut_ok / ref_mut_conflict（Step 3 新增）
```

### MS-2.4-4（闭包绑定 → name_res 可解析为可调用类型）

**条件：** `let f = (x: number) => x + 1; f(5)` → `let f` 绑定类型为 `HirType::Function(...)`，`Call(Ident("f"), …)` 的 typeck 能识别 callee。

**根因：** `resolve_block_names` 在 `let_s.ty == HirType::Error` 时调用 `infer_type_from_expr`，而 `infer_type_from_expr` 对 `HirExpr::ArrowFn` 落入 `_ => HirType::Error`（未映射为 `Function`）。

**实现策略（二选一，推荐 A）：**
- **A：** `infer_type_from_expr` 新增 `HirExpr::ArrowFn` 分支 → `HirType::Function(param_tys, ret)`（参数/返回未定型时用 `HirType::Error` 占位，与 `typeck::expr_type` 对 `ArrowFn` 的行为一致）
- **B：** `HirStmt::Let` 分支在 `init` 为 `HirExpr::ArrowFn` 时跳过 `infer_type_from_expr`，直接写入 `Function` 类型

`check_expr` `HirExpr::Call` 分支与 `check_call` **无需改动**（已支持 `HirType::Function`）。

**验证：**
```bash
cargo test -p trust_hir -- closure_call_resolves
```

### MS-2.4-5（闭包调用 → typeck 通过 + codegen 生成正确 Rust）

**条件：** `let f = (x: number) => x + 1; f(5)` 整个管线通过，codegen 产出合法 Rust。闭包体编译为独立 `fn`，调用处生成函数调用。

**实现策略（Phase 2.4 最小可用路径）：**
- typeck：`expr_type` 对 `ArrowFn` 返回 `HirType::Function(params, ret)`（已有逻辑）；`check_call` 验证实参/形参匹配（已有逻辑）
- TIR：`lower_expr` `ArrowFn` 分支已提升为独立 `TirFunction`，`captured_vars: Vec<CapturedVar>` 记录捕获（`tir.rs` 现有路径）
- codegen：已支持 `TirFunction` + `captured_vars`（`codegen.rs` 现有路径）；闭包调用生成 `closure_N(args)`
- **不在 2.4：** `move` 闭包的 FnOnce 语义强制、嵌套闭包的捕获链——归后续 Phase

**验证：**
```bash
cargo test -p trustc -- e2e_closure_call   # Step 3 新增
```

## 4. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| borrowck 借用冲突实现复杂度超预期 | 低 | 中 | 冲突规则已在 `borrowck.rs`；2.4 仅补 `&mut` 发射路径 + 测试 |
| 闭包捕获的 codegen 路径不完整 | 中 | 中 | `TirFunction.captured_vars` 和 codegen 已有框架；2.4 聚焦简单只读捕获，`move` 闭包归后续 |
| `&mut` 解析与位运算 `&` 歧义 | 低 | 低 | `&mut` 是双 token（`&` + `mut`），不与位运算 `&` 混淆（位运算 `&` 是中缀，`&mut` 是前缀） |
| serde 引入导致二进制膨胀 | 中 | 低 | 评估文档产出决策；若成本过高则坚持手写（当前零依赖） |
| 闭包调用与现有 `Function` 调用路径冲突 | 低 | 中 | `HirType::Function` 统一表示可调用类型；`ArrowFn` → `Function` 映射已在 `expr_type` 中实现 |
