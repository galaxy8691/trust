## 0. 文件说明

本规格书定义 **Phase 2.1**（移除旧设计废弃语法/类型 + 关键字表重核 54→43 + spec 对齐 v2.0）的工程范围、成功标准、验收条件。

**背景：** Phase 1 在 v2.0 设计重构前交付，编译器仍包含 `loop`/`bigint`/`interface`/`impl`/`select`/`undefined`/`Option`/`Result`/`Box`/`dyn`/`extends` 等已废弃关键字与语义。本里程碑在所有 crate 中**系统性移除这些残留**，将关键字表从 54 重核为 43，并同步修正 `spec/trust-spec.md` 使其对齐 v2.0。这是 Phase 2 的**第一个里程碑**——所有后续 2.2/2.3/2.4/2.5 均依赖本里程碑完成。

**运算符边界（v2.0）：**
- **保留：** 前缀 `!x`（逻辑非，`TokenKind::Bang`）、`?.`（空值链）、`??`（空值合并）
- **本里程碑移除：** 后缀 `expr!`（旧 Option 断言 → `Expr::AssertUnwrap`）、后缀 `expr?`（旧 Result 传播 → `Expr::TryPropagate`）。v2.0 分别由 null 安全（Phase 4）与 `try-catch`（Phase 4）替代

**一句话成功：** `cargo build --workspace` 通过，`grep` 验证所有旧设计关键字/类型/AST 节点已清理，关键字表 43 个，`spec/trust-spec.md` 废弃条目已删除，`spec/stdlib.md` 无用户面 Option/Result。

## 2. 实现步骤

### Step 1：关键字表重核（lexer）— 预计 0.5 天

**文件：** `crates/trust_parser/src/lexer.rs`

1. 在 `static KEYWORDS` 中删除 16 个废弃条目，新增 5 个条目（每项附带 `// 设计 §X.X` 注释）
2. 在 `TokenKind` 枚举中删除对应 16 个变体，新增 5 个变体
3. 更新文件头注释：`54 个关键字` → `43 个关键字`；`6 种字面量` → `5 种字面量`（移除 `BigIntLiteral`）
4. 更新 `TokenKind::can_end_stmt`：移除 `None_`/`BigIntLiteral`，替换为 `null` 等新 token（**保留 `Bang`**——仅前缀逻辑非 `!x`）
5. 确保 `BigIntLiteral` 字面量 token 变体同步移除（`Nn` 后缀字面量不再识别）
6. **确认已存在无需操作：** `type` / `match` / `throw` / `shared` / `spawn` 均已存在于当前 lexer
7. **更新 lexer 单元测试：** `lex_keyword_count_is_54` → `lex_keyword_count_is_43`、删除 `lex_bigint_literal_returns_bigint_token`、新增 `lex_null_literal`

**验证：** `cargo build -p trust_parser` 预期编译失败——lexer 删除变体后 parser 必然报错（引用 `TokenKind::Loop`/`Select`/`Interface`/`Impl`/`BigIntLiteral`/`None_` 等）。记录错误清单到 `docs/phases/2/2.1/build-errors-step1.txt`，进入 Step 2 后随 parser 同步修复。
