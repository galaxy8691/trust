## 0. 文件说明

本规格书定义 **Phase 2.1**（移除旧设计废弃语法/类型 + 关键字表重核 54→43 + spec 对齐 v2.0）的工程范围、成功标准、验收条件。

**背景：** Phase 1 在 v2.0 设计重构前交付，编译器仍包含 `loop`/`bigint`/`interface`/`impl`/`select`/`undefined`/`Option`/`Result`/`Box`/`dyn`/`extends` 等已废弃关键字与语义。本里程碑在所有 crate 中**系统性移除这些残留**，将关键字表从 54 重核为 43，并同步修正 `spec/trust-spec.md` 使其对齐 v2.0。这是 Phase 2 的**第一个里程碑**——所有后续 2.2/2.3/2.4/2.5 均依赖本里程碑完成。

**一句话成功：** `cargo build --workspace` 通过，`grep` 验证所有旧设计关键字/类型/AST 节点已清理，关键字表 43 个，`spec/trust-spec.md` 中废弃条目已删除。

## 1. 成功标准

### MS-2.1-1（关键字表 54→43）

**条件：** `crates/trust_parser/src/lexer.rs` 中 `static KEYWORDS` 映射表包含恰好 43 个条目，`TokenKind` 枚举包含恰好 43 个变体（不含字面量 token），文件头注释为 `//! 43 个关键字`。

**移除的 16 个关键字及其 TokenKind 变体：** `loop`, `bigint`, `interface`, `impl`, `select`, `undefined`, `None`, `Some`, `Ok`, `Err`, `Rc`, `Arc`, `Weak`, `Box`, `dyn`, `extends`（含 `BigIntLiteral` 字面量 token）

**新增的 5 个关键字及其 TokenKind 变体（仅 lexer 预留，表达式/语句实现归后续 Phase）：** `unknown`（Phase 3）、`try`/`catch`（Phase 4）、`null`、`panic`（Phase 4）

**验证：**
```bash
# 关键字数量 = 43
grep -c '=> TokenKind::' crates/trust_parser/src/lexer.rs
# 预期: 43

# 头注释正确
head -3 crates/trust_parser/src/lexer.rs | grep '43 个关键字'
```

## 2. 实现步骤

### Step 1：关键字表重核（lexer）— 预计 0.5 天

**文件：** `crates/trust_parser/src/lexer.rs`

1. 在 `static KEYWORDS` 中删除 16 个废弃条目，新增 5 个条目（含 `// 设计 §X.X` 注释）
2. 在 `TokenKind` 枚举中删除对应 16 个变体，新增 5 个变体
3. 更新文件头注释：`54 个关键字` → `43 个关键字`
4. 更新 `TokenKind::can_end_stmt`：移除 `None_`/`BigIntLiteral`/`Bang`，替换为 `null` 等新 token
5. 确保 `BigIntLiteral` 字面量 token 变体同步移除

**验证：** `cargo build -p trust_parser` 通过（此时 parser 尚未更新，可能有编译错误——记录并进入 Step 2）

### Step 2：移除 `loop`（端到端）— 预计 1 天

**文件：** `crates/trust_parser/src/ast.rs`、`parser.rs`、`crates/trust_hir/src/`、`crates/trust_tir/src/`、`crates/trust_codegen/src/`

1. **AST：** 删除 `Stmt::Loop(LoopExpr)` 变体与 `LoopExpr` 结构体；删除/禁用 `BreakStmt.value` 字段
2. **Parser：** 移除 `loop { ... }` 解析分支；`break value` 不再合法 → 若 parser 遇到 `break expr` 报错
3. **HIR：** 移除 `Loop`/`LoopExpr` 降级逻辑
4. **TIR：** 移除 `Loop` 对应 borrowck/moveck 路径
5. **Codegen：** 移除 `loop` → Rust `loop { ... }` 生成分支

### Step 3：移除 `bigint` — 预计 0.5 天

**文件：** `crates/trust_parser/src/ast.rs`（`Type::BigInt`）、`parser.rs`、`crates/trust_hir/src/`、`crates/trust_codegen/src/`

1. **AST：** 删除 `Type::BigInt` 变体
2. **Parser：** 移除 `bigint` 类型标注解析路径 + i64 字面量解析
3. **HIR typeck：** 移除 `BigInt` 类型检查规则
4. **Codegen：** 移除 `bigint` → Rust `i64` 映射

### Step 4：移除 `interface`/`impl`/`select` 关键字残留 — 预计 0.5 天

**文件：** `crates/trust_parser/src/parser.rs`、`ast.rs`

1. **Parser：** 移除 `interface`/`impl` 关键字同步点（Phase 1 未实现语义，仅清理预留）
2. **AST：** 删除 `select` 转义槽（若有）
3. 注：lexer 关键字移除已在 Step 1 完成，此步仅清理 parser/AST 残留

### Step 5：移除其余旧设计残留 + `null` 映射 — 预计 0.5 天

**文件：** `crates/trust_parser/src/parser.rs`、`ast.rs`、`crates/trust_hir/src/`、`crates/trust_codegen/src/`

1. **Parser：** 更新 `can_expr_start`（移除 `None_`/`BigIntLiteral`/`Loop`/`Bang`，替换为 `null` 等新 token）
2. **`null` 映射：** parser 中 `null` 关键字 → `Expr::Null`（取代旧 `None_→Expr::Null` 路径）
3. **HIR/Codegen：** 若存在对 `Option`/`Result` 类型的内置翻译逻辑，一并移除（这些类型在 v2.0 不再暴露给用户）
4. **全仓 grep 验证：** 执行 MS-2.1-2 的 grep 命令确认无残留

### Step 6：规范对齐 v2.0 — 预计 0.5 天

**文件：** `spec/trust-spec.md`、`docs/phases/0/0.3/audit-report.md`

1. 删除 `spec/trust-spec.md` 中已废弃条目（见 MS-2.1-6）
2. 在旧审计报告顶部插入废止声明（见 MS-2.1-7）
3. 建立章节冻结矩阵（记录在 spec 或本规格书中）

### Step 7：编译验证 + 失败清单 — 预计 0.5 天

1. `cargo build --workspace` 必须通过
2. `cargo test --workspace` 运行，收集因旧 AST 移除导致的临时测试失败
3. 将失败清单写入 `docs/phases/2/2.1/known-failures.md`（由 2.5 统一修复）

| `ferro_rt` | **无** | 不变 |

## 4. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 移除旧 AST 节点导致大量测试编译失败 | 高 | 中 | Step 7 收集失败清单，不阻塞 2.1 验收；2.5 统一修复 |
| `&` token 歧义（Reference vs 未来的 BitAnd） | 低 | 低 | Phase 2 不在本里程碑处理位运算；`Amp` 保留用于 Reference，位运算 token 预留到 2.2.5 |
| `null` 映射后 HIR/TIR 对 `Expr::Null` 的处理不完整 | 中 | 低 | 仅保证 lexer→AST 路径；完整 null 安全语义在 Phase 4 落地 |
| spec 修改范围大导致遗漏 | 中 | 中 | 按 MS-2.1-6 的 grep 逐条核验 |
