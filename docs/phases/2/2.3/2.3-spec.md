## 1. 成功标准

### MS-2.3-1（块体函数缺失返回标注 → 编译错误）

**条件：** `function f(...) { ... }` 形式（非 `= expr` 表达式体）在无 `: ReturnType` 标注时，name_res 降级阶段产出编译错误。

**错误信息：** `"块体函数必须显式标注返回类型。无返回值时使用 \`:void\`"`  
**错误码：** `E0062`（新增；`trust_error::ErrorCode` 枚举登记）  
**严重级别：** Error（编译失败，不产出代码）  
> **实现注记：** name_res/typeck 当前使用 `DiagError`（消息字符串，**不携带** `ErrorCode`）。`E0062` 完整集成归 H-X-01；验收以消息 `"块体函数必须显式标注返回类型"` 为准。

**合法场景：**
- `function f(): void { ... }` → 通过
- `function main(): void { ... }` → 通过（入口函数同样须 `:void`，无特殊豁免）
- `function f(): number { return 42; }` → 通过
- `function f(): string { return "hi"; }` → 通过

**非法场景：**
- `function f() { }` → 错误（即使无 return 语句）
- `function f() { return 42; }` → 错误
- `function f() { return; }` → 错误（即使只返回 void）
- `function add(a: number, b: number) { return a + b; }` → 错误
- `export function f() { return 42; }` → 错误（export 路径经同一 `lower_function` 检查）

**验证：**
```bash
# name_res 块体标注检查（typeck 不重复此项）
grep -n '必须显式标注返回类型' crates/trust_hir/src/name_res.rs
grep -n 'E0062' crates/trust_error/src/diagnostic.rs

cargo test -p trust_hir -- block_body_missing_return_type export_block_body_missing_return_type
```

### MS-2.3-2（表达式体函数 → 返回类型由表达式推断）

**条件：** `function f(...) = expr` 形式在无 `: ReturnType` 标注时，返回类型由 `expr` 的类型推断，且推断结果正确。

**示例：**
| 源码 | 推断返回类型 |
|------|-------------|
| `function sq(x: number) = x * x` | `number` |
| `function greet(name: string) = \`Hello, ${name}\`` | `string` |
| `function isPositive(n: number) = n > 0` | `boolean`（无专项 HIR 测试；`number`/`string` 推断路径已覆盖） |
| `function getUnit(): number = 1` | `number`（标注优先，非推断） |

**验证：**
```bash
cargo test -p trust_hir -- expr_body_infer_number expr_body_infer_string expr_body_annotated_return
```

### MS-2.3-3（表达式体函数标注与推断一致）

**条件：** `function f(...): T = expr` 形式标注了返回类型时，若 `expr` 推断类型与 `T` 不一致 → 类型不匹配错误（消息形如 `type mismatch: expected ...`；规范编号 `E0308`，实际 `DiagError` 占位同 E0062）。

**验证：**
```bash
cargo test -p trust_hir -- expr_body_type_mismatch     # Step 5 新增
```

### MS-2.3-4（箭头函数返回类型推断 + 可选返回标注）

**条件：**

1. **推断：** `(x) => expr` 或 `(x) => { return expr; }` 在无返回标注时，`typeck` 将 `HirType::Error` 哨兵替换为 `infer_return_type(body)`。
2. **返回标注：** 设计 §4.1 语法 `(x: number): number => x * 2`（`: ReturnType` 在 `=>` 之前）。`parser::try_parse_arrow_params` 解析；`name_res` 写入 `ArrowFn.ret`；有标注时跳过推断。

**未标注参数类型 `(name) => expr`：** 归 **Phase 3 隐式泛型**（H-P3-07a）；2.3 保证类型化参数 + 推断路径不回归。

**验证：**

### Step 2：块体函数强制返回标注（name_res 降级时检查） — 预计 0.25 天

**文件：** `crates/trust_hir/src/name_res.rs`、`crates/trust_error/src/diagnostic.rs`

**2a — `trust_error::ErrorCode` 新增：**
- [x] `diagnostic.rs`: `ErrorCode` 枚举新增 `E0062` 变体，注释 `/// 块体函数缺少返回类型标注`
  > **注意：** E0062 当前为文档编号。name_res/typeck 使用本地 `DiagError`（无 `code` 字段），实际诊断输出不携带错误码。`E0062` 的完整集成（Diagnostic + ErrorCode）由 H-X-01（各 crate 迁移至 `trust_error::Diagnostic`）统一执行。

**2b — `lower_function` 块体检查：**
- [x] 在 `lower_function()` 中，`f.return_type` 为 `None` 且 `!f.is_expression_body` 时：
  - 推送 `DiagError::new("块体函数必须显式标注返回类型。无返回值时使用 `:void`", f.span.clone())`
  - HIR `return_type` 回退为 `HirType::Void`（允许后续 typeck 继续检查 body；此时若 body 含 `return expr`，typeck 将产出额外的 `return type mismatch` 级联错误——此为**可接受的附加诊断**）
- [x] **export 路径：** `lower_exports` → `lower_function` + `HirItem::Function` 入 `items`；`register_module_bindings` 跳过重复注册
- [x] 表达式体函数 `f.return_type` 为 `None` 时 → HIR `return_type` 设为 `HirType::Error`（信号：需推断）
- [x] `f.return_type` 为 `Some(t)` 时 → HIR `return_type` 从 AST 映射（现有逻辑不变）

**设计决策——为何检查在 name_res 而非 typeck：** `lower_function` 持有 AST `FunctionDecl` 引用，直接可见 `return_type: Option<Type>` 与 `is_expression_body: bool`。typeck 层只有 HIR（`return_type: HirType` 已丢失 "是否显式标注" 信息），若在 typeck 判断需额外标记字段。在降级点检查更简洁，且与"缺失标注→编译错误"的语义一致：name_res 就已经可以判定语法层面的缺失。

### Step 3：表达式体函数返回类型推断（typeck） — 预计 0.25 天

**文件：** `crates/trust_hir/src/typeck.rs`

**3a — `check_function` 推断逻辑：**
- [x] 在 `check_function()` 末尾，`check_block` 执行后：
  - 若 `func.is_expression_body && func.return_type == HirType::Error`：
    - 调用 `infer_return_type(&func.body)` 推断返回类型
    - 将推断结果写回 `func.return_type`
  - 若 `func.is_expression_body && func.return_type != HirType::Error`（用户显式标注）：
    - 不做推断，直接使用标注类型（现有 `check_block` 已验证 Return 语句类型一致性）

**3b — `infer_return_type` 复用：**
- [x] 现有 `infer_return_type()`（`typeck.rs`）扫描 body 中首个 `Return` 语句的表达式类型。表达式体函数的 body 含唯一一条合成 `ReturnStmt { value: Some(expr) }`，推断结果即为 `expr` 的类型——现有逻辑直接适用，无需修改
- [x] 边缘情况：若表达式体为 `function f() = { }`（空块作为表达式——语法虽合法但无意义），推断为 `Void`

> **隐式依赖声明：** 表达式体推断逻辑依赖 parser 将 `= expr` 包装为仅含一条 `ReturnStmt { value: Some(expr) }` 的 `Block`（`parser.rs::parse_fn` 表达式体分支）。若未来 parser 调整此包装方式，需同步更新推断逻辑。

> **技术债务：** `HirType::Error` 在此处承担"需推断"信号，与 typeck 中"类型检查失败"哨兵共享同一变体。箭头函数沿用同一模式（`typeck` `HirExpr::ArrowFn` 分支）。Phase 3+ 可拆分为 `HirType::Infer` / `HirType::Error` 两个独立变体以消除语义重载。

## 4. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 现有 `.trust` 测试夹具含无标注块体函数 | 低 | 低 | 实际扫描 48 个 `.trust` 夹具——**0 个**未标注块体函数（均已标注 `:void`/`:number` 等）。风险转移到 Phase 3 新增功能时引入的夹具 |
| `is_expression_body` 漏传导致块体误判为表达式体 | 低 | 中 | parser 快照测试覆盖两种路径；name_res 中显式 boolean 传递不加条件 |
| 表达式体推断与标注冲突时级联错误 | 低 | 低 | typeck 哨兵 `HirType::Error` 跳过后续比较，避免级联 |
| 箭头 `(x): T =>` 与 `(x: T): R =>` 语法混淆 | 中 | 中 | 统一采用设计 §4.1：`(params): ReturnType =>`；测试与 trust-spec EBNF 同步 |
| parser 箭头扩展引入 `(expr)` 与箭头歧义 | 低 | 中 | 仅当 `)` 后紧跟 `=>` 或 `: type =>` 时判为箭头；否则保持括号表达式 |
| 2.5 集成测试中无标注块体夹具需改写 | 低 | 低 | 扫描现有 `.trust` 夹具已符合规则；`snap_fn_inout`/`snap_fn_move` 已补 `:void` |
| typeck 推断失败后 `return_type` 保持 `Error` | 低 | 低 | typeck 错误 → 编译中止 → 不进入 codegen（Phase 1/2 不变量） |
