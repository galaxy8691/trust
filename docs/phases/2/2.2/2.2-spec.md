# Phase 2.2 — `number` 统一为 f64 规格书

> 版本：v1.0 · 分支：phase2-v2-align · 对齐：`docs/phases/2/TODO.md §2.2`
> 里程碑代号：2.2-NUMBER-F64 · 期限：Phase 2 第 3–4 周（1–1.5 周）

---

## 0. 文件说明

本规格书定义 **Phase 2.2**（`number` 统一为 f64 + 整数语义 + 位运算）的工程范围、成功标准、验收条件。

**背景：** Phase 1 将 `number` 拆分为 `i32`（整数）与 `f64`（浮点），禁止混算，要求显式 `as` 转换。v2.0 设计 §2.2 合并为单一 `number`=f64，自由运算，仅位运算有 `number` 专用约束。本里程碑在 HIR typeck + codegen 层**彻底移除 i32/f64 分离**，落地整数语义（数组索引/循环/长度/2^53 警告），并**新增位运算**（token/AST/parser/typeck/codegen 完整路径）。这是 Phase 2 v2.0 语义修正的**核心里程碑**——自此 Trust 编译器使用统一的 `number` 类型。

**前序相关清理：** 2.1 已移除 `bigint`/`BigIntLiteral`/`I64`/`BigInt` 及旧 `i32`/`f64`/`i64` 区分中的 `i64` 路径。剩余的 `I32`/`F64` 分立及 `i32+f64→error` 规则在本里程碑清除。

**⚠️ 关键前置：** 整数字面量当前全链路为 `IntLiteral(i32)`（lexer→AST→HIR→TIR），无法承载 >2^31 的值。本里程碑须将载荷类型升级为 `f64`（Step 1d），否则 2^53 精度警告无从落地。

**一句话成功：** `let a = 42; let b = 3.14; let c = a + b;` 编译通过并生成 `f64` 运算，`arr[n]` 自动插 `as usize`，`9007199254740993` 触发 `Warning`。

## 1. 成功标准

### MS-2.2-1（HIR typeck：i32/f64 分离已移除）

**条件：** `crates/trust_hir/src/hir.rs` 中 `HirType` 枚举不再含 `I32`/`F64` 两个变体，合并为单一 `Number` 变体。`from_ast_type` 将 `Type::NumberType` 映射为 `HirType::Number`（不再映射为 `I32`）。

**验证：**
```bash

# 预期: 0 匹配（仅剩注释或 Number/Array 行）

# from_ast_type 映射正确

# 预期: NumberType => HirType::Number
```

### MS-2.2-2（HIR typeck：i32+f64→error 规则已移除）

**条件：** `crates/trust_hir/src/typeck.rs` 中不再有 `i32`/`f64` 混算报错逻辑。`number` 之间所有算术运算（`+`/`-`/`*`/`/`/`%`/`**`）自由通过。

**验证：**
```bash

```

**验证：**

**验证：**

### MS-2.2-5（整数语义落地）

**条件：**

| 场景 | 实现 | 验证 |
|------|------|------|
| 数组索引 `arr[n]` | codegen 生成 `arr[n as usize]` | e2e 测试：`let x = arr[1]` → 生成的 Rust 含 `as usize` |
| 循环计数 `for (let i=0; i<N; i++)` | `i` 类型为 `number`(f64)，`i++` 等价 `i += 1.0` | typeck 验证推断结果 |
| 长度/容量 `.length` | 返回 `number`(f64) | codegen 验证 `usize`→`f64` 装箱 |
| 超 2^53 精度警告 | `Warning` 级别诊断（`Severity::Warning`），附 `Help` 子诊断说明精度风险 | e2e 测试：`let big = 9007199254740993;` → 编译 warning |
| FFI 整数 | Phase 2 仅建立 `number`→`f64` 默认映射，跨边界转换延后 Phase 7 | 无测试（延后） |

**验证：**


### MS-2.2-6（`as` 收敛）

**条件：** parser 中 `as number` / `as f64` / `as i32` 的解析路径已移除。`as` 仅用于非 `number` 转换（如未来 `unknown`→具体类型，Phase 3）。设计依据：`number` 统一后这些 `as` 为恒等变换，保留会允许无意义代码。

**验证：**
```bash
# typeck 层：is_valid_as_cast 拒绝对 NumberType 的 as 转换
grep -rn 'Number.*as\|as.*Number' crates/trust_hir/src/typeck.rs
# 预期: 0 匹配（number 之间 as 恒等变换已移除；非 number 的 as 保留）
```

### MS-2.2-7（位运算完整路径）

**条件：** lexer/parser/AST/HIR typeck/codegen 全链路支持 `&`/`|`/`^`/`<<`/`>>` 位运算。

**子条件 7a — lexer token：** `|` 识别为 `TokenKind::Pipe`（不再退化为 `Ident`）；`^`→`Caret`、`<<`→`Shl`、`>>`→`Shr` 新增；`&` 在 parser 中按上下文区分 `Amp`（前缀 `&x`）与 `BitAnd`（中缀 `a & b`）。

**子条件 7b — AST/parser：** `BinOp` 枚举含 `BitAnd`/`BitOr`/`BitXor`/`Shl`/`Shr`；`parse_binary` 处理位运算中缀，优先级 `<<>>` > `&` > `^` > `|`。

**子条件 7c — HIR typeck：** 位运算操作数仅允许 `number` 类型。非 `number` → 编译错误。

**子条件 7d — codegen：** `f64::to_bits()`→`u64`→位运算→`f64::from_bits()` + `/* bitwise on f64: behavior per IEEE 754 */` 注释。

**验证：**
```bash
cargo test -p trust_parser -- bitwise
cargo test -p trust_hir -- bitwise
# 端到端测试（2.5 中集成）
```

### MS-2.2-8（编译通过 + 测试不劣化）

**条件：** `cargo build --workspace` 通过。因 `I32`/`F64` 移除导致的测试更新全部完成。2.1 禁用的测试（参见 `docs/phases/2/2.1/known-failures.md`）继续禁用，不引入新禁用。


## 2. 实现步骤

### Step 1：HIR 类型统一 — 预计 0.5 天

- [ ] 删除 `HirType::F64` 变体（L256）
- [ ] 新增 `HirType::Number` 变体（替代上述两个）
- [ ] 更新 `from_ast_type`：`Type::NumberType => HirType::Number`
- [ ] 更新 `as_rust_type`：`HirType::Number => "number"`（合并旧 I32/F64 分支）
- [ ] 更新 `Display for HirType`：`HirType::Number => write!(f, "number")`
- [ ] 更新 `hir.rs` 单元测试：`I32`/`F64` 引用改为 `Number`

**1b — typeck 运算规则移除（`typeck.rs`）：**
- [ ] 删除 `i32 + f64 → error` 类型不匹配规则
- [ ] 所有算术运算的类型检查改为接受 `HirType::Number`
- [ ] 一元 `-` 允许 `Number`
- [ ] `as` 转换中移除 `I32`→`F64`/`F64`→`I32` 相关规则（保留非 number 转换路径）
- [ ] 删除 `I32`/`F64` 在 `is_copy_type` 中的旧引用（如有）
- [ ] 整数字面量推断：`IntLiteral` → `HirType::Number`（当前为 `I32`）

**1c — moveck 更新（`moveck.rs`）：**
- [ ] `is_copy_type`：`HirType::Number` 判定为 Copy

**1d — 整数字面量载荷类型升级（全链路 `i32`→`f64`）：**
- [ ] `lexer.rs`: `IntLiteral(i32)` → `IntLiteral(f64)`；解析逻辑改为 `s.parse::<f64>().unwrap_or(0.0)`
- [ ] `ast.rs`: `Expr::IntLiteral(i32)` → `IntLiteral(f64)`
- [ ] `hir.rs`: `HirExpr::IntLiteral(i32, Span)` → `IntLiteral(f64, Span)`
- [ ] `tir.rs`: `TirValue::IntLiteral(i32)` → `IntLiteral(f64)`
- [ ] 各层匹配分支同步更新（`IntLiteral(v)` 模式中的 `v` 类型变为 `&f64`）

- [ ] 移除 `I32`↔`F64` 转换规则
- [ ] parser 层 `AsCast` 路径保持不变——类型检查在 typeck 层完成；为 Phase 3 `unknown`→具体类型预留通用 `as` 机制

### Step 4：整数语义 — 预计 0.5 天

**文件：** `crates/trust_codegen/src/codegen.rs`、`crates/trust_hir/src/typeck.rs`

- [ ] **数组索引：** 当前 TIR 无专门 Index 操作，索引通过 `TirOp::Call` 或 `MemberAccess` 实现。确定具体接入点后，codegen 自动插入 `as usize`（如 `format!("{}[{} as usize]", arr, index)`）
- [ ] **循环计数：** 2.2 不新增 `i++`/`+=` 语法（归 Phase 3）。验收用例改用 `i = i + 1`。typeck 确认 `for (let i=0; i<N; i=i+1)` 中 `i` 推断为 `Number`
- [ ] **长度/容量：** codegen 中 `.length` → 返回时 `usize as f64` 自动转换
- [ ] **超 2^53 精度：** 在 HIR typeck 中添加字面量范围检查——依赖 Step 1d 的 `IntLiteral(f64)`，检查 `v > 9007199254740992.0 || v < -9007199254740992.0` → `Diagnostic::warning(...)` + `Diagnostic::help("超出 IEEE 754 安全整数范围，可能丢失精度")`
- [ ] 数组索引为非整数时发出 `Warning`

### Step 5：位运算完整路径 — 预计 1–1.5 天

**文件：** `crates/trust_parser/src/lexer.rs`、`ast.rs`、`parser.rs`、`crates/trust_hir/src/`、`crates/trust_codegen/src/codegen.rs`

**5a — lexer（`lexer.rs`）：**
- [ ] `|` 字面量：从当前退化为 `Ident("|")` 改为识别为 `TokenKind::Pipe`
- [ ] `&` 保留 `TokenKind::Amp`（因 `&x` 引用语义仍需保留）；中缀 `a & b` 由 parser 按上下文区分
- [ ] `^` → 新增 `TokenKind::Caret`
- [ ] `<<` → 新增 `TokenKind::Shl`
- [ ] `>>` → 新增 `TokenKind::Shr`

**5b — AST（`ast.rs`）：**
- [ ] `BinOp` 枚举新增：`BitAnd`、`BitOr`、`BitXor`、`Shl`、`Shr`

**5c — parser（`parser.rs`）：**
- [ ] `parse_binary` 新增位运算中缀解析
- [ ] 优先级（lbp/rbp）：`<<`/`>>` (lbp=10, rbp=9) > `&` (lbp=8, rbp=7) > `^` (lbp=6, rbp=5) > `|` (lbp=4, rbp=3)。`|` 高于 `&&` (lbp=6)，确保 `a | b && c` 按 `(a | b) && c` 解析
- [ ] `TokenKind::Amp` 在**前缀位置**（`parse_unary`）→ `Expr::Reference`
- [ ] `TokenKind::Amp` 在**中缀位置**（`parse_binary`）→ `BinOp::BitAnd`

**5d — HIR typeck（`typeck.rs`）：**
- [ ] `check_binary_op`：`BitAnd`/`BitOr`/`BitXor`/`Shl`/`Shr` → 操作数必须为 `HirType::Number`
- [ ] 非 Number 操作数 → 编译错误

**5e — codegen（`codegen.rs`）：**
- [ ] 位运算 codegen 策略：`f64::to_bits()` → `u64` 位运算 → `f64::from_bits()`
- [ ] `bin_op_str` 新增 `BitAnd`→`&`、`BitOr`→`|`、`BitXor`→`^`、`Shl`→`<<`、`Shr`→`>>` 分支
- [ ] 统一注释：`/* bitwise on f64: behavior per IEEE 754 */`
- [ ] 示例：`a & b` → `f64::from_bits(a.to_bits() & b.to_bits()) /* bitwise on f64: behavior per IEEE 754 */`

### Step 6：测试与快照更新 — 预计 0.25 天

- [ ] 更新 HIR typeck 测试中引用 `I32`/`F64` 的用例 → `Number`
- [ ] 更新 codegen 测试中预期输出 `i32` → `f64`
- [ ] 移除 `i32 + f64 → error` 相关的测试用例（或改为验证合法）
- [ ] 新增位运算解析 + typeck 测试

## 4. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| I32/F64 移除导致大量 typeck 测试失败 | 高 | 中 | Step 1 优先改 HIR typeck 核心路径，测试跟随更新 |
| `&` 歧义（Reference vs BitAnd）导致解析错误 | 中 | 中 | 按位置区分：前缀=Reference，中缀=BitAnd。若某个上下文无法区分，parser 报错提示加括号 |
| `|` 改为 Pipe 后影响现有退化 Ident 的行为 | 低 | 低 | 当前 `|` 退化为 Ident 已是非预期行为，改为 Pipe 是修复 |
| f64 位运算 codegen 语义正确性 | 中 | 中 | codegen 策略为 `to_bits→u64→位运算→from_bits`，行为遵循 IEEE 754；附加注释说明 |
| 2^53 精度警告误报 | 低 | 低 | 仅对字面量常量值 > 2^53 检查；运行时计算的 number 不检查 |
